# 凍結：REod Tier 1

**2026-08-17 凍結。以後変更しない。**

## これは何か

REod の最初の設計と、その完全な実装（Rust 2,115行、テスト 1,104行、82テスト、clippy 0）。
カーソル機械——AST を持たず、トークン列上をカーソルが走りながら実行する——として書かれている。

## なぜ凍結したか

設計の根本的な見直しに入ったため。捨てる判断をしたのは次の3つ。

1. **動的スコープ** — 名前をコンパイル時にスロットへ解決できず、性能の床を作っていた
2. **既定の遅延評価** — PHECL 原則7（処理順序を人間から隠蔽しないこと）違反。実測で4人の読み手全員が実行順序を誤読した
3. **波括弧の多義性** — 裸のブロック／`if` 本体／ループ本体が同じ記法で異なる規律を持っていた。PHECL 戒1（同じ構文に異なる意味を割り当て、差異を設計者が暗黙に解決する）に該当

保持するものは [../../docs/](../../docs/) 側の分析文書を見よ。

## 消さずに残す理由

**これは測定器である。** 再設計の過程で出た結論のほぼ全部が、この実装を実際に走らせて得たものだった。

```
cd legacy/reod-tier1
./target/release/reod examples/plain1_numbers.reod < /dev/null
cargo test
```

新設計を検証するときの神託として使う。保持すると決めた意味論（領域・akasha・`;`・作用素式・動的段数の `break`）が
新旧で同じ答えを出すかは、ここで確かめられる。

## 引き継ぐべきもの

`docs/decisions.md` の却下理由は、新設計でも同じ罠を避けるために効く。
現に、再設計の過程で **D-70 の却下理由に誤りが見つかった**——`:=` の代わりに中立な記号を使う案を
「移行コスト」を理由に却下したが、PHECL 本文（「示唆できないのなら一切示唆するべきではない」）に照らすと
そちらが正道だった。
