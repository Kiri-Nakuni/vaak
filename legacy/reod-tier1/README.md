# REod

PraTeX 埋め込みスクリプト言語 **REod**（read と同じ発音。REod means just read）のインタプリタ。拡張子は `.reod`。

`言語設計書.md` の核となる意味論を Tier 1 まで実装したもの。

```bash
cargo test                                   # 意味論のスナップショットテスト
cargo run -- examples/ex3_collatz.reod       # 設計書 例3（関数版）
cargo run -- examples/ex5_comefrom.reod      # 設計書 例5
cargo run -- examples/ex6_goto_reset.reod    # 設計書 例6
```

## 引き返せない設計判断

「最小限」を機能のサブセットではなく、**実行アーキテクチャへのコミット**として定義している。

| | |
|---|---|
| [src/lexer.rs](src/lexer.rs) | 字句解析のみ。構文解析はしない |
| [src/state.rs](src/state.rs) | 束縛と、TeX の save stack と同型の状態管理 |
| [src/interp.rs](src/interp.rs) | カーソルマシン。読んだそばから実行する |
| [src/prelude.reod](src/prelude.reod) | 無名標準ライブラリ。中核ではない（D-37） |

### 1. プログラム全体の AST を構築しない

設計書 §4.3 が要求するのは「通過していない区間はパースされていない」こと。例4 の `fast_module` が存在しなくてよいのも、マクロによる括弧不整合が走査の通過時点で初めて検出されるのも、これに依る。AST インタプリタで作ると後から絶対に足せない。

トークン化は先行して行う（TeX も文字→トークンの変換は先行する）。マクロ層を載せる際は catcode 相当の再トークン化が要る。

### 2. 状態は TeX の save stack そのもの

- `{ }` は3つの意味を持つ（D-23）。スコープを作るのは裸のブロックと関数本体だけ
- `#[global]` は最下層へ直接書き、**全レベルから当該セルの undo エントリを除去**する（D-4）
- jump は全レベルの journal を内側から適用して空にするが、**レベル構造は保存する**（D-5）——jump はブロック構造を変えず状態だけを戻す

トップレベルではレベルが1つしかないので記録が起きない。「トップレベル＝global」（§4.8）が特別扱いではなくこの条件から自然に出る。

### 3. thunk は環境を捕捉しない

§4.6 の「名前解決自体も強制の瞬間まで先送りされる」を、**式のトークン範囲だけを持ち、強制時の状態で名前を引き直す**ことで実装している。この一点から3つのことが出る：

- 再帰に不動点コンビネータは不要（かつクロージャなしでは構成不能）。`#[forward]` は**名前の存在チェックを抑止する属性**であって機構ではない（D-6）。検査は `let` の右辺だけに掛かるので（D-30）、関数の再帰には `#[forward]` は要らない
- 左辺が右辺に現れる代入は発散する（D-17）。`#[immediate]` か複合代入が要る。**`+=` は `:=` の糖衣ではない**（D-24）
- **関数の引数は呼出側で即時強制される**（D-20）。遅延したままだと自由名が呼ばれた側の局所束縛で引き直され、関数のインタフェースでないものがインタフェースになってしまう——クロージャ不採用から導かれる

### 4. アトリビュートは「次の行」を修飾する

`#[global, immediate]` のようにリストで書き、行末で終端する（D-18r）。`global`（書き込みレベル）と `immediate`（評価時点）は直交する2つの操作なので束ねない。関数定義の返り値型も同じく改行で終端する（D-21r）。

### 5. `break` はループ専用ではない

`break E;` は E を正格に評価して**そのブロック**の値とし、ブロックを終了する（D-28）。関数本体で使えばそれが返り値になるので、`return` は存在しない。`if` / `else` の本体は状態にも `break` にも透明なので、素通しして外側の本物のブロックが受け止める。

`continue` はループの次の周回へ移るが、ブロックを出ないので巻き戻しは起きない（D-29）。`goto` で同じ場所へ飛べば巻き戻る——差は「ブロックを出たか」だけ。

### 6. 作用素式——値でも関数でもマクロでもない第4の圏

`break X;` は「このブロックを正常に終了し、続けて X を**外側の文脈で**行う」の一つの意味論（D-38）。X が式ならブロックの値になり、X が制御移動（`break` / `continue` / `goto`）ならそれが外側で起きる。

```
break break 2;              % 2段抜ける
break goto done;            % 閉じてから跳ぶ（裸の goto と違い巻き戻さない）
$repeat(break, getdepth()) v; % 深さがいくつであれ関数を抜ける
```

**`$` を読んだ時点で作用素の評価規則へ入る**（TeX の catcode 切り替えと同型）。入ったあとは印を重ねない。作用素は値ではないので束縛に入れられない——D-27（関数は第一級ではない）と同じ線。

`flow` は作用素式に名前を与える第3の束縛種で、本体は**使用のたびに使用位置で**読み直される（D-39）。thunk を作らないので束縛演算子ではなく `=` を使う（D-42）。フレームを積まないので `getdepth()` が使用位置の深さを見る。

`return` は組み込みではなく、[src/prelude.reod](src/prelude.reod)（無名標準ライブラリ）の1行:

```
flow return = $repeat(break, getdepth());
```

同じ機構が `flow sneaky = $repeat(break, getdepth() - 1);` も書ける。**名前を付けられるということは、抜ける範囲を名前の裏に隠せるということ**であり、`return` が安全なのは `getdepth()` がちょうど正しいからであって機構が安全だからではない。「足元を撃つ自由」（§1.6）に対し、**規律を組む自由**を同じ機構で与える。

## 実装済み

`%` コメント / `i64` / `let`（値）/ `fn`（関数、D-27）/ `:=` `&=` `^=` / `+=` `-=` `*=` `/=` / `#[immediate]` `#[global]` `#[forward]`（リスト可）/ 関数定義・呼び出し（再帰・相互再帰含む） / `if` `else`（式としても） / `loop` / `break`（任意のブロックから、値あり・なし） / `continue` / 作用素式（`break` の入れ子・`$repeat`・`break goto`・`break comefrom`）/ `flow` 束縛 / `$frame` / `getdepth()` / `goto` `label` `comefrom`（フレーム境界による隠蔽つき） / ブロックの末尾式 / `let` 右辺の名前存在チェック / `print` / `read` / 算術・比較・短絡論理 / `mod`

`return` は中核にない。無名標準ライブラリの作用素別名（D-26r / D-39）。

`tests/semantics.rs` は設計書のコード例と decisions.md の確定事項をそのまま回帰テストにしている。仕様書とテストが同じものを指していれば、例と本文の食い違いは構造的に起きなくなる。
