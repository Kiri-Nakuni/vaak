# REod 概要

REod の記述的要約。何がどうあるか、どんな概念があるかだけを書く。設計理由・経緯・他言語との比較は含まない。

---

## コメント

`%` から改行までを、**改行を含めて**飲む。飲まれた区間は何も産まない。

行末 `%` は行継続になる。アトリビュートは行末で終端するので、その後ろにコメントは置けない。行番号は物理行で数える。

---

## 実行モデル

逐次実行のインタプリタ。プログラム全体の構文解析を事前に行わない。カーソルがトークン列を進み、読んだそばから実行する。

通過していない区間は解析されない。`goto` で読み飛ばされた区間は構文的に壊れていてもよく、その区間の名前も未定義でよい。

埋め込み向け言語であり、プログラムの値とエラーはホストへ渡る。

---

## 領域

**領域**は値が置かれる場所。入れ子になる。演算子の各引数位置、ブロック、プログラム全体がそれぞれ領域である。

> どの領域も、実在する値を高々1つしか持てない。

```
[ [1] + [2] ]      左に1つ、右に1つ、全体に1つ
1 2                エラー（1つの領域に値が2つ）
```

消費されなかった値は外側の領域の値になる。プログラム全体の領域の値がホストへ渡る。ソースが `1` だけのプログラムは、ホストに 1 を渡す。

領域の値の個数は静的に決まる（演算子の引数の数と `;` の有無から）。

---

## akasha と paradox

規則は3行に尽きる。

1. 領域は**ちょうど一つ**の値を持つ。内部に何も置かれていなければ、その値は **paradox**
2. `;` は左の値を**評価してから**捨て、内部を空にする
3. paradox は消さねばならない。消費するのは `;`、`??`、そして**ホスト**

「何もない」は2種類ある。**領域が空である**ことと、**値だが中身がない**こと（paradox）。前者に名前は要らないが、区別は要る。

`;` は最低優先度の後置単項演算子で、**評価してから**捨てる。`hoge()` は何も起こさず、`hoge();` は hoge を呼ぶ。

`{ e1; e2 }` は e1 を強制して捨て、e2 を返す。

```
1; 2; 3        プログラムの値は 3
1; 2; 3;       領域に何も置かれない
```

空のプログラムの値は paradox であり、ホストはそれを「値なし」と解釈する。

**paradox** は値であり、領域を占める。表示は `{}`。

出どころは2つ——宣言（`let` / `fn` / `typ` / `flow`）と制御移動（`goto` / `continue`）が返す、空の領域が読まれたとき。

消えかたも2つ——`;` が潰す、構文上書かれた型注釈が既定値を置く。どちらも起きないまま領域が終了すればエラー。

```
{ 5 }          値は 5
{ 5; }         中身が空 → 読まれる → paradox
{}             同上
let x := 5     paradox が残ったまま領域が終わる → 不正
let x := 5;    潰される → 正しい
let x := {};   右辺の領域が束縛の時点で終わる → 不正
f({})          引数の領域が終わる → 不正
```

文の位置のブロック式にも `;` が要る。

```
if c { n := 5; };
loop { … };
```

丸括弧は領域を作らない。項の列を持てるのは波括弧だけである。`(1; 2)` は不正。

paradox を消すにはフォールバック演算子を使う。

```
E ?? F      E が paradox なら F、そうでなければ E。F は短絡
```

```
d[k] ?? 0                欠損キーなら 0
d[k] ?? 0 - 1            欠損キーなら -1
if c { 5 } ?? 0          偽なら 0
nfor (i in 0..n) { … } ?? 0    範囲が空なら 0
{} ?? 0                  0
```

優先順位は最低（`;` の直上）。型注釈は値を生成しない。

## 型

数値型：`i64` `u64` `i32` `u32` `f32` `f64` `f80` `u8` `u16`

組み込みパラメトリック型（後置形式）：

- `T array` — T の値を u64 キーで引く
- `T U hashmap` — T の値を U キーで引く
- `T U pair` — 第1要素 T、第2要素 U

`str` は `u8 array` の別名。`paradox`。

ADT なし。クロージャなし。多相はユーザーが書けない（組み込みコンストラクタは多相）。

型付けは**読み取り時検査**。読んだ範囲が読んだ時点で検査される。推論は関数内に限定される。

型注釈は2形式。束縛子には `:`、式には `->`。

## 束縛

| | 記号 | thunk | 本体をいつ読むか |
|---|---|---|---|
| `let x := E;` | `:=` `&=` `^=` | 作る | 強制時に1回（メモ化） |
| `fn f (…) { … } -> T;` | なし | 作らない | 呼び出しごと（フレームを積む） |
| `typ T { … };` | なし | 作らない | — |
| `flow p = …;` | `=` | 作らない | 使用ごと（メモ化しない、フレームを積まない） |

- `a := E` — E から新しい thunk を生成する
- `b &= a` — a が指している thunk そのものを共有する
- `c ^= a` — a が保持している未評価の計算を複製する

**名前解決は常に解決時点の環境で行われる。** thunk も関数本体も、定義位置の環境を保持しない。**関数も動的スコープである。**

```
let x := 1;
fn f () { x } -> i64;
{ let x := 2; f() }     2
```

```
let a := 5;
let b := a;
let c ^= a;
{ let a := 999; b }     999
c                        5
```

新規導入には `let` が必要。再束縛は `let` なし。宣言はすべて `;` で終端する。

関数・作用素は第一級ではない（`let g := f;` は不正）。

`let` の右辺は名前の存在検査を受ける。`fn` の本体は受けない。関数の再帰は属性なしで動く。`fn` 本体のタイプミスは呼び出し時まで見つからない。

複合代入 `+= -= *= /=` は左辺の現在値を即時強制する。`x := x + 1` は自己参照 thunk になり発散するが、`x += 1` は動く。

## アトリビュート

```
#[global, immediate]
x := x / 2;
```

リストで書く。**行末で終端し、次の行を修飾する。** 同じ行に文を続けることはできない。

| | |
|---|---|
| `#[immediate]` | 束縛の**前**に強制する |
| `#[global]` | 書き込みを巻き戻しから除外する |
| `#[forward]` | 名前の存在検査を抑止する |
| `#[flat]` | `goto` 専用。走査からブロック構造の認識を外す |
| `#[lazy_attribute]` | 次のアトリビュートを遅延させ、使用位置で効かせる |

`global` と `immediate` は独立している。

---

## ブロックとスコープ

波括弧は**値を産む領域**を作る。巻き戻しの規律は、その括弧が何に付いているかで決まる。

| 括弧が付いている先 | スコープの規律 |
|---|---|
| `if` / `else` | 付けない（透明） |
| `loop` / `while` / `ifor` / `nfor` | チェックポイント |
| `fn` | グループ（フレーム） |
| 何にも付いていない | グループ |

**グループ**：抜ける際に journal を適用する。ブロック内で新たに行われた変更のみが対象。レジスタ層書き込みとヒープ書き込みに一様。

**チェックポイント**：レベルを push するが pop しない。正常に抜けるときは journal を**適用せず破棄**する（変更が確定する）。jump が発火したときだけ適用される。

ただし `comefrom` の登録だけは、チェックポイント破棄時にも適用される。

**`#[global]`**：最下層へ直接書き、全レベルから当該セルの undo エントリを除去する。トップレベルはレベルが1つしかないので元から global 相当。

**jump の巻き戻し**：`continue` 以外の jump は、跨いだブロックの数に関わらず、発火のたびに非 global 状態を一括で巻き戻す。レベル構造は pop しない。降りられるのは現在のフレーム基底までである。

## 制御構造

すべて式である。

### `if` / `switch`

```
if (cond) { … } else { … }

switch kind {
    0 => …;
    _ => …;
}
```

`&&` / `||` は短絡評価する。

`else` のない `if` は偽のとき領域が埋まらない。値として使うなら型注釈が要り、そのとき偽の場合は既定値になる。`_` の腕のない `switch` も同様。値を出す腕どうしは型が一致していなければならない。

### ループ

4つは**反復回数を何が決めるか**だけで違う。

| 構文 | 反復回数 | 完走時に領域を埋めるもの |
|---|---|---|
| `nfor (i in 0..n) { … } -> T` | 開始前に確定した範囲 | 最後の周回の末尾式 |
| `ifor (x in it) { … } comp { … }` | 反復子 | なし（出口が決める） |
| `loop { … }` | `break` | なし（`break` が決める） |
| `while (cond) { … }` | 条件が 0 になるまで | 反復回数そのもの |

| 構文 | `break v` | `break;` | `comp` |
|---|---|---|---|
| loop | 必要 | 可 | 不可 |
| while | 不可 | 可 | 不可 |
| nfor | 不可 | 可 | 不可 |
| ifor | 可 | 可 | 可 |

`while` の値は反復回数。条件は任意の数値型を取り、0 が停止を意味する。

いずれの構文も本体の性格は制約しない。`nfor` の本体に `while` を書ける。

## 作用素式

```
作用素式 := 作用素* 終端
作用素   := 'break' | '$repeat(' 作用素 ',' 式 ')' | 別名
終端     := 式 | 制御文 | ε
制御文   := 'continue' | 'goto' L | 'comefrom' L | 'label' L
```

> `break X;` — このブロックを正常に終了し、続けて X を**外側の文脈で**行う。

X が式ならその値がブロックの値になる。X が制御移動ならそれが外側の文脈で行われる。

`if` / `else` の本体は break に対して透明であり、段数を消費しない。

**`$` を読んだ時点で作用素の評価規則に入る。** 入ったあとは印を重ねない（`$repeat(break, 2)`）。

`$repeat(op, n)` の第1引数は `break` / `continue` / 別名。`break` を重ねればブロックを n 段抜け、`continue` を重ねれば反復を n 個進める。`goto` は重ねられない。**第2引数は動的でよい。**

`getdepth() -> u32` は、現在のフレーム内で開いているブロックの数を返す。すなわち、この関数（トップレベルならプログラム）を抜けるのに `break` を何回重ねる必要があるか。`break` が吸収されるレベルだけを数えるので `if` の本体は入らない。

`$frame { … }` は呼び出しを伴わない depth 基準を張る。

`flow` は作用素式に別名を与える。本体は使用のたびに使用位置で読み直され、フレームを積まない。本体は終端を含んでよいが、その場合使用位置に終端を重ねられない。

```
flow return = $repeat(break, getdepth());
```

`break` は関数境界を越えられない。

### `break goto` と `goto`

裸の `goto` は jump なので一括巻き戻しを起こす。`break goto L` はブロックを正常に閉じてから跳ぶので起こさない。

```
loop { acc += 1; goto done; }        acc は巻き戻る
loop { acc += 1; break goto done; }  acc は残る
```

### `break comefrom`

`comefrom` は唯一、実行が続く終端である。`break` が先にブロックを閉じるので、登録されるのは外側の文脈である。

```
fn hoge () { { break comefrom T; }; write(1, $s, "x"); label T; 0 } -> i64;
```

x が出続ける。

## jump

意味は3行に尽きる。

1. `comefrom` は位置をコンテクストに保存する。名前ごとに1エントリを持つ可変マップへ、通過するたびに「戻り先＝この文の直後」を無条件で上書き登録する
2. `goto` は対応する `label` の直前まで読み飛ばす。走査はマクロを展開せず、波括弧の深さのみを認識する。着地はカーソル移動以上の意味を持たない
3. `label` は保存されている `comefrom` があればその直後へ飛び、さもなくば何もしない

**jump は depth 基準を跨げない。** より内側の基準の中も、より外側も**見えない**。エラーではなく隠蔽であり、3 により `label` は何もしない。`goto` だけは行き先が要るので、フレーム内に見つからなければエラーになる。

4つがこの一つの境界を共有する：`getdepth()` の原点、`break` の上限、jump の巻き戻しの下限、`goto` の走査範囲。

**跳び先は、それを含む構文が開いている間だけ生きる。** 外から飛び込むことはできない。飛び出しはできる。

ラベル名はフレーム局所である。

depth 基準を跨ぐ唯一の手段は `break` である。

## 関数とディスパッチ

```
fn getroot (uf : uf_tree, idx : u64) {
    if (uf.parent[idx] == idx) { idx }
    else { … }
} -> u64;
```

返り値型は後置 `->`。省略は本体からの推論。引数の型は推論可能なら省略できる。

**引数は呼出側で即時強制される。**

メンバ関数（`object.operation(args)`）を持つ。ユーザーも定義できる。単相。

> ディスパッチは静的に決まらなければならない。

許される：返り値型によるオーバーロード（呼出側の `-> T` で決まる。引数の個数は常に一致することを要求する）、レシーバの型によるメンバ関数の解決。

禁じられる：実行時の値によるディスパッチ、関数境界を越える推論を要する解決、候補の比較を要する解決。

## 入出力

`read()` は入力を消費する。切り出し単位は返り値型で決まる（`-> str` は行、数値型はトークン）。

```
write(fd, 書式, 引数...)
```

第1引数は POSIX のファイルディスクリプタ。第2引数は**レンダリング方針**を指す字句トークン（`$s` はテキスト表現、`$x` は16進表現）で、文字列ではない。第3引数以降は結合される。各引数は自分の静的型に応じて方針でレンダリングされる。

```
write(1, $s, "count: ", n);
```

**左から順に評価しながら出力する。** 中間バッファを作らない。途中の引数の評価が失敗すれば、そこまでの出力は既にストリームへ出ている。返り値を持たない。

---

## エラー

エラーは値にならない。ADT を持たないので error union は構成できない。処理系内部の失敗（配列範囲外、括弧不整合など）は即座にホストへ伝播する。

ホストへ渡るものは2種類。正常終了の値（トップレベルの領域の値）と、エラー。

---

## 名前空間

`let` / `fn` / `typ` / `flow` は名前空間を1つ共有し、後の宣言が遮蔽する。

---

## 層

中核仕様と、すべてのプログラムの前に無名で読み込まれる標準ライブラリの2層。標準ライブラリは REod で書かれている。

標準ライブラリにあるもの：`str`、`return`、**ブロックコメント**、`printstr` / `printi32` 等（すべて `write` の糖衣）。

```
flow return = $repeat(break, getdepth());

#[lazy_attribute]
#[flat]
flow comment = goto _comment_;
```

ブロックコメントの使用：

```
comment;
    ここは壊れていてよい { { {  undefined( 1 2 3
label _comment_;
```

飛ばされる区間は**字句解析だけは通る必要がある**。入れ子にならない。`_` で始まるラベル名はユーザーの使用を企図しない。

各糖衣の脱糖は仕様に字句どおり書かれる。

## 評価戦略

束縛はデフォルトで遅延評価される（memoizing thunk）。強制が起きる地点は次に尽きる。

| 強制点 |
|---|
| `;` |
| `#[immediate]` |
| 関数の引数 |
| `+=` `-=` `*=` `/=` の左辺 |
| `break` の引数 |
