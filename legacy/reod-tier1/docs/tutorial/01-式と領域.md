# 第1章 式と領域

## 最も短いプログラム

```
1
```

これで完結した REod のプログラムである。

説明できることが3つある。

- `1` は**式**である
- **プログラム全体が1つの領域**である
- 領域の値が**ホスト**へ渡る

ホストとは REod を埋め込んでいるプログラムのことで、REod を単体のコマンドとして走らせているなら OS がホストになる。このプログラムを走らせると、ホストは 1 を受け取る。

多くの言語は最初のプログラムとして画面に文字を出す例を見せる。あれを説明するには、文字列とは何か、入出力とは何か、`main` とは何か、実行環境とは何かを同時に持ち出すことになる。ここではそのどれも要らない。

## 領域とは何か

**領域**（contextual region）は、値が置かれる場所である。規則は一つ。

> **どの領域も、実在する値を高々1つしか持てない。**

さきほどのプログラムでは、プログラムという領域に値 1 が置かれていた。

では、2つ置いたらどうなるか。

```
1 2
```

エラーになる。「構文が間違っている」のではない——`1` も `2` も文法的には完全に正しい式である。**プログラムという1つの領域に、値が2つ置かれた**ことがエラーの理由である。

エラーメッセージもそう言う。「文の書き方が違います」ではなく「領域に値が2つあります」と言う。何が起きたかを言っていて、書き方を叱っていない。

> ちなみに、この規則は書かれたものを見るだけで確かめられる。プログラムを走らせなくても、値がいくつ置かれているかは数えられる。

## 領域は入れ子になる

ここで疑問が出るはずである。

```
1 + 2
```

これは通る。しかし `1` と `2` という値が2つ書かれている。さっきの規則に反しないのか。

反しない。**`1` と `2` はそれぞれ別の領域にいる**からである。

```
[ [1] + [2] ]
```

`+` は左右に一つずつ領域を持ち、そこから値を取り、**自分の領域に結果を一つ置く**。外側の領域に置かれるのは 3 だけである。

比較でも同じことが起きる。

```
1 == 1
```

同じ値が2つ見えるが、それぞれ別の領域にいて、`==` がその2つを消費して真偽（REod では数値）を1つ置く。

```
[ [1] == [1] ]
```

領域はブロックより狭い。**演算子が引数を取る場所、その一つ一つが領域**である。だから領域の数は演算子の引数の数から決まり、これも見れば分かる。

先ほどの `1 2` が通らなかったのは、`1` と `2` を消費して結果を置いてくれるものが間に無いからである。2つの値が、行き先のないまま同じ領域に並んでいた。

## 領域を自分で書く

波括弧を書くと、領域を明示的に作れる。

```
{ 1 + 2 }
```

このプログラムの値は 3 である。波括弧の中が一つの領域で、そこに 3 が置かれ、それが外側の領域（プログラム）に置かれる。

入れ子にもできる。

```
{ { 1 } }
```

値は 1 である。

波括弧は**中身を値として取り出す**。この規則は後の章でもう一度出てくる——中身が空のときに何が起きるかは3章で扱う。

> 波括弧には、領域を作ること以外の役割もある。それは4章で扱う。ここで言えるのは「値を産む領域を作る」ことだけである。

## 値が消費されなくてもよい

`1 + 2` では、`1` と `2` は `+` に消費された。しかし消費は必須ではない。

```
1
```

この `1` は誰にも消費されず、そのままプログラムという領域の値になった。**消費されなければ、その値は外側の領域の値になる**。それだけである。

だから「一番外側で消費されなかった値がホストへ渡る」という言い方もできる。最初のプログラムが説明できたのは、この規則のおかげである。

## この章のまとめ

- REod のプログラムは式である
- **領域**は値が置かれる場所で、値を高々1つしか持てない
- 領域は入れ子になる。演算子の引数の位置がそれぞれ領域である
- 消費されなかった値は外側の領域の値になる
- プログラム全体も領域であり、その値がホストへ渡る
- 波括弧は領域を明示的に書く
