# 小式言語 #2：`wrap` で番号に名前を付ける

**Codex の arena 提案（未決定）に対する対照実験。**

`codex/selfhost-arena-probe` の [`07-セルフホスト骨格.vaak`](../../examples/vaak/07-セルフホスト骨格.vaak)
は、節を `Node array` に平坦化し、子を**裸の `i64`** で指している。

提案は `arena` と `T handle` を一級機能にして、**番号の取り違えを型で止める**ことを狙う。

**その利得のうち、どれだけが `wrap` で今日取れるか**を測った。

同じ入力（`12 + 3 * (4 + 5) + 6 / 2` → 42）を、`wrap NodeId = i64` を足しただけの版で通した。
実物は [`08-包み型の番号.vaak`](../../examples/vaak/08-包み型の番号.vaak)。

## 結論

| | |
|---|---|
| **取り違えは止まる** | 二種類の番号を混ぜると**組み立て時に断られる** |
| **費用はゼロ** | 生成された**機械語が完全に一致**した |
| **書く量は増える** | 剥がし 10 箇所、包み 5 箇所、変わったのは 21 行 |
| **止まらない誤りもある** | 「同じ型の別の番号」は型では区別できない |

## 取り違えは本当に止まる

トークンの位置を節の番号として使う、という現実によくある誤りを両方に入れた。

```text
裸の i64   →  黙って 0 を返す（誤った答え）
wrap       →  型が合わない（`NodeId` が要るのに `TokenId`）
```

**片方は走ってしまう。** これが利得の本体である。

ただし**「同じ型の別の番号」は止まらない。** `new NodeId(i)` と包んでしまえば通る。
arena 提案も同じ限界を認めている（「同じ `Ast` 型の arena instance 二つの取り違えまで
型だけでは防げない」）。

## 費用はゼロだった

STEEL で両方を組み立て、`clang -O2 -S` まで通して機械語を比べた。

```text
arena 版と wrap 版の .s は、.file と .ident を除いて完全に一致
```

実行時間も 749 µs 対 748 µs で、差は測定の揺らぎの中である。

**S-2 の「包みは実装から見れば基底型である」が、機械語の水準で確かめられた。**

## 書く量

```text
総行数     272 → 276     （+4）
変わった行  21
剥がし（-> i64）  10 箇所
包み（new NodeId） 5 箇所
```

剥がしが要るのは**添字と比較**である。

```
nodes[id -> i64]                       添字に包み型は使えない
if ((id -> i64) < 0) …                 比較に包み型は使えない
```

## 見つかった穴

### 1. 包み型が**添字にも比較にも使えない**

```
var i : NodeId := new NodeId(1);
a[i]                  →  添字にできない値
i < new NodeId(3)     →  比較できない値どうし
```

S-2 は「**配列・写像のメソッドは、ラップした先に直接効く**」としか言っていない。
**演算子と添字については書かれていない。**

比較（`<` `==`）は次元の意味を壊さないので、通してよいはずである。
掛け算は違う（`Meters * Meters` は `Meters` ではない）。**ここは決定が要る。**

添字は「`i64` に落ちる包み型なら添字に使える」でよいと思うが、
これも書かれていないので決定が要る。

### 2. STEEL が**関数の返りで包みを剥がしていなかった**（直した）

```
fn parse (…) { … } -> NodeId;
let root := parse(…);
evaluate(nodes, root)     →  clang: '%t89' defined with type 'ptr' but expected 'i64'
```

定義側では剥がしていたが、**呼び出し側で剥がしていなかった**ので、
`NodeId` が構造体と間違えられて `ptr` になっていた。

**この実験で見つかった。** 差分試験を足して直した。

## 提案への読み方

arena 提案が狙う「番号の取り違えを型で止める」は、**`wrap` で今日ほぼ取れる。**
費用もゼロである。

残る差は二つ。

1. **`.alloc(v)` が一手で番号を返す**（今は `push` してから `len() - 1` を包む）
2. **`arena[h]` 以外で辿れない**（今は生の配列なので、他の添字でも触れる）

そして提案には**書き換えの道が書かれていない。** 例は `let node := ast[root]` で
**写し**を取っている。コンパイラなら `ast[h].kind := 5` が要る。
配列なら `nodes[i].kind := 5` は**もう書ける。**

上の穴 1（比較と添字）を決めて塞げば、`wrap` 版の剥がしは 10 箇所から**ほぼ零**になる。
**そこまでやってから、arena がまだ要るかを見るのが順序だと思う。**

## 再現

```bash
vaak examples/vaak/08-包み型の番号.vaak            # → 42
steel examples/vaak/08-包み型の番号.vaak > a.ll
clang -O2 -o a.out a.ll -lm && ./a.out; echo $?    # → 42
```
