# Safe Rust で同じ S 式評価器を書く

[Vaak 版](lisp.md)と同じ整数 S 式を Safe Rust だけで二通りに実装し、書き味と
調整余地を比べました。実装は
[examples/support/rust_lisp.rs](../../examples/support/rust_lisp.rs)、計測器は
[examples/bench_lisp_rust.rs](../../examples/bench_lisp_rust.rs) にあります。

これは Vaak の言語仕様を増やす提案ではなく、実装済みの道具でどこまで性能設計を
表現できるかを見るための対照実験です。外部 crate は足しておらず、新規コードには
`#![forbid(unsafe_code)]` を置いています。

STEEL native と同じ process から交互に測った最終比較は
[小 LISP の別名調整と Safe Rust 比較](lisp-performance.md)に分けています。

## 揃えた意味

両実装は、Vaak 版と同じ次の形を受け取ります。

| 形 | 意味 |
|---|---|
| 整数、名前 | `i64` 値、最も内側の字句束縛 |
| `(+ ...)`, `(* ...)` | 零個以上を左から畳む |
| `(- ...)`, `(/ ...)` | 一個以上を左から畳む。単項 `-` は符号反転 |
| `(= a b)`, `(< a b)` | 真なら 1、偽なら 0 |
| `(if condition yes no)` | 選んだ腕だけ評価する |
| `(let name value body)` | 本体だけに見える字句束縛 |
| `(do ...)` | 順に評価して最後の値。空なら 0 |

整数演算は Vaak と同じく折り返し、除算はユークリッド除算です。零除算、未知の名前、
壊れた構文は `Result` の誤りになります。Vaak 版の主入力そのものも両方で 42 になることを
試験しています。

比較対象は正しい入力の意味です。不正入力に対する受理範囲まで同一ではありません。Rust 版は
先に構文木全体を作るため、選ばれない `if` の腕に未知の演算子や余分な引数があっても構文誤りに
します。Vaak 版は構文木を作らず、選ばない腕では括弧の深さだけを調べるため、その内容を評価せず
通過できます。性能表には正しい入力だけを使うので、この差は計測結果に影響しません。

## 二つの Rust 実装

### 素朴版

`naive` は字句を所有する `String` に分け、再帰的な `enum` の構文木を作ります。環境は
`Vec<(String, i64)>` です。`let` に入るたびに環境全体を `to_vec()` し、束縛名も複製します。

これは Rust で最初に書きやすい形です。再帰的な式を `enum` へそのまま写せるため、構文と
データ表現が近くなります。環境の複製は字句スコープを簡潔にしますが、深さ `d` の
入れ子では写す要素数の合計が二次的に増えます。名前の `String` も複製するので確保回数が
増えます。

### 調整版

`tuned` は次を行います。

- 入力文字列を借用したまま走査し、字句ごとの `String` を作らない
- 名前を一度だけ intern し、評価時は `u32` の `Symbol` を比べる
- 構文木を `Vec<Node>` の arena に置き、参照は `u32` の `NodeId` にする
- 可変長の子も別 arena のリンクに置き、構文ノードごとの `Vec` 確保を避ける
- 最大の字句束縛深さを構文解析時に求め、環境の容量を一度だけ予約する
- `let` では一組を push し、本体から戻ったら必ず pop する
- 評価だけを繰り返すときは `Evaluator` と確保済み環境を使い回す

arena の中は添字だけなので、自己参照構造や `unsafe` は要りません。`Program` は intern した
名前を入力から借りるため、Rust の生存期間が「入力は構文木より長生きする」という条件を
型に残します。

## 計測方法

次で同じ nested-let 入力を生成します。

```bash
cargo run --release --example bench_lisp_rust -- \
  --depth 48 --iterations 2000 --samples 7
```

調整版だけを測り直す場合は `--only-tuned` を加えます。素朴版の大量確保で CPU の温度や
動作周波数を変えずに済むため、STEEL との横比較ではこちらを使います。

`--depth N` は概ね次の形を作り、答えは `N - 1` です。

```lisp
(let x0 0 (let x1 1 ... (let x47 47 x47)...))
```

各標本では `std::time::Instant` を使い、一演算当たりの時間を求めます。標本の中央値を
代表値にします。ループ中の答えは `std::hint::black_box` に渡しています。

- `parse+eval`: 毎回、同じ文字列を解析してから評価する
- `eval-only`: 解析済み表現を繰り返し評価する。調整版は環境の確保領域も再利用する

任意の同一入力を両実装へ渡すには `--source EXPR` または `--file PATH` を使います。
集計するときは `--tsv` を加えます。Vaak 側との横比較では `--depth`、`--iterations`、
`--samples` を同じにし、同じ生成式を渡します。

## 今回の測定値

Windows NT 10.0.26200、Intel Core i7-13620H、`rustc 1.98.0`、MSVC release build で、
各 1000 反復を 9 標本測りました。単位は一回当たりの中央値、µs です。

| 深さ | naive 解析込み | tuned 解析込み | naive 評価だけ | tuned 評価だけ |
|---:|---:|---:|---:|---:|
| 8 | 4.580 | 1.432 | 2.300 | 0.046 |
| 24 | 32.580 | 3.140 | 24.928 | 0.258 |
| 48 | 107.680 | 6.635 | 78.554 | 0.717 |
| 96 | 584.221 | 15.424 | 335.203 | 0.809 |

Vaak 版の主例（70 bytes、答え 42）も 10000 反復、9 標本で測ると、naive は解析込み
3.142 µs／評価だけ 0.356 µs、tuned は解析込み 1.141 µs／評価だけ 0.073 µs でした。

これはマイクロベンチマークであり、プロセサ固定、割り込みの除外、確保器の置換までは
行っていません。特に naive の深い入力は確保が多く、標本間の揺れも大きくなりました。
絶対値より、深さを増やしたときの傾向を見る表です。

この入力では最も内側の名前だけを読むため、名前探索はどちらもほぼ一回です。差の中心は
`let` ごとの環境複製です。深さ 96 の評価だけでは、push/pop 版が複製版より二桁以上短く、
深さを増やしても二次的な複製量を作りません。解析込みでも、借用字句、intern、arena が
確保回数を抑えています。

## 書き味

Rust の素朴版は、再帰的な `enum` と `Result` が S 式へ素直に対応します。中心部分は短く、
誤りの型も明示できます。一方、性能を詰めると表現の層が増えました。この時点の実装では、
素朴版の module が約 290 行、調整版が約 520 行です。`NodeId`、`Symbol`、子リンク、intern、
容量見積もりの管理が、速さと引き換えに見えるコードとして残ります。

Vaak 版は再帰的な値型を持たないため、「平らなトークン列＋次位置」の形を最初から選びます。
これは構文木を作らない小さな評価器にはよく合います。ただし `if` の非選択腕を `skip` する
処理が要り、構文を増やすほど評価と読み飛ばしの対応を保つ仕事が増えます。

環境については、Vaak の深い複製は素朴版と同じ安全で簡潔な書き方を与えます。性能を
詰めるときは Rust 調整版と同様に、可変配列を作業スタックとして push/pop する形が必要です。
この用途に専用の stack 型は必須ではありません。重要なのは、配列を別名で一つだけ共有し、
要素を戻せることです。

構文木についても、必要なのは自己参照する値より「arena＋安定した整数 ID」です。これは
Vaak の配列と整数で表せます。将来の Vaak-on-Vaak を妨げないために先に確認すべきなのは、
専用 stack の有無より、arena、名前 intern、ソース span を余計な深い複製なしに扱えるかです。

## 検証

```bash
cargo test --release --test rust_lisp
```

試験は主例、全演算、字句的 shadowing、遅延する `if`、整数の折り返し、日本語名、
深さ 96 の生成入力、構文誤り、実行時誤りを両実装で照合します。新規三ファイルは
`rustc -D warnings` でも検査し、`unsafe` を禁止しています。
