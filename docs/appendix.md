# Vaak を読むための付録

この付録は、構文を覚えるためではなく、Vaak のコードをどう頭の中で動かすかを説明します。
すぐにコードを書きたい場合は [Vaak リファレンス](reference.md) から始めてください。

ここで扱う「領域」「内界面」「外界面」「Akasha」「paradox」「脱出」は、別々の機構です。
似た言葉へ急いで置き換えるより、まずこの六つをそのまま区別する方が、結果的に近道です。

## 1. 中心にある像：領域は一つの置き場

Vaak の式は、それぞれ自分の領域で評価されます。一つの領域が外へ見せられる値は高々一つです。
領域には、内側から結果を置く面と、閉じた後に外側から結果を見る面があります。

```text
領域の内側                       領域の外側

計算 ──→ 内界面 ──［領域を閉じる］──→ 外界面 ──→ 次の計算
```

| 用語 | 見る向き |
|---|---|
| 内界面 | 領域の中で、計算が値を置く側 |
| 外界面 | 領域が閉じた後で、外から一つの結果として見る側 |

普通の値が一つ置かれれば、その値が外へ見えます。

```vaak
{ 40 + 2 }       % 内界面に 42、外界面にも 42
```

値を二つ置こうとすれば、どちらがその領域の値なのか決められないため静的エラーです。

```vaak
{ 1 2 }          % 値が二つ
```

Vaak の読み方の第一歩は、「どこが領域か」「その内側に最後まで何個の値が残るか」を数えることです。

## 2. 「何も無い」は値ではない

領域の中に値が一つも残っていない状態を、このリポジトリの設計記録と実装は
**Akasha（アーカーシャ）** と呼ぶことがあります。人間向けの仕様では「何も無い」または「虚無」と
書かれることもあります。

重要なのは名前よりも、次の否定です。

- Akasha は `0` ではありません。
- 空文字列や空配列ではありません。
- `null` ではありません。
- `void` や `unit` という一個の値でもありません。
- 型ではなく、領域を一枡も占めません。

たとえば `;` は左の結果を捨て、領域の内側を Akasha にします。

```vaak
{ 42; }
```

この領域の内側には何も残りません。しかし、領域を外から見る側は「何も無い」を直接値として
受け取れません。そこで、領域を閉じると外界面は paradox になります。

```text
内界面                         外界面

通常の値 V       ──閉じる──→  V
Akasha           ──閉じる──→  paradox
paradox          ──閉じる──→  paradox
```

「内側に何も無い」と「外から値を要求したが値が無い」は違います。Akasha と paradox の区別は、
この内側と外側の区別です。

最上位だけは、外界面の向こうに Vaak ではなくホストがいます。したがって、プログラム全体が
`;` で終わったときの扱いはホストが決めます。スタンドアロン版は何も表示せず正常終了します。

## 3. paradox は型の外に紛れ込む null ではない

Vaak では、型 `T` の式は外界面に `T` の値か paradox を置きます。設計上は
`T ⊕ paradox` という直和です。ただし利用者が `Option<T>` を構築したり、タグを読んだりする
仕組みではありません。

セルが保存できるのは `T` の値だけです。paradox を変数へ入れて後から見つけることはできません。

```vaak
let x := 1 / 0;          % x に入る前、値を要求する境界でエラー
let x := 1 / 0 ?? 0;     % paradox の腕をその場で除き、0 を入れる
```

paradox を受け付ける演算子は二つだけです。

| 演算子 | 働き |
|---|---|
| `;` | 結果を捨て、内界面を Akasha にする |
| `??` | paradox なら右辺で置き換え、通常の値ならそのまま通す |

他の演算子は値を要求します。したがって paradox がそれらに出会うと、後ろの `??` までは
届きません。

```vaak
(1 / 0) ?? 42            % 42
(1 / 0) + 2 ?? 42        % + が先に値を要求するのでエラー
f(1 / 0)                 % 引数の領域が値を要求するので f には届かない
```

paradox そのものは理由を運びません。「見つからなかった」と「空だった」を呼び分ける必要がある
API は、区別を通常の値として設計します。`??` が答えるのは「値があったか」だけです。

この仕組みが null と異なる線は明確です。paradox はセルへ保存できず、発生した領域の近くで
`??` により値へ戻すか、`;` により捨てるか、値を要求した境界でエラーになります。

## 4. `;` は句読点ではなく消去

多くの言語を知っているほど、`;` を「文の終わり」と読みたくなります。Vaak では、意味から先に
読んだ方が正確です。

```vaak
var x := 1;
x += 2;
x
```

ここで `;` が必要なのは改行を終えるためではありません。宣言と代入は値を残さず、外から見ると
paradox だからです。`;` がその結果を消して、次の式を同じ領域へ置けるようにします。

```vaak
{ a; b; c }      % a と b を消し、c だけを残す
{ a; b; c; }     % c も消し、内側は Akasha
1;;              % 一度目も二度目も「消す」という同じ操作
```

この像があれば、「どの行にセミコロンを付けるか」という一覧を暗記する必要はありません。
その結果を次へ渡すなら残し、渡さないなら消します。

## 5. 領域、スコープ、脱出段は別物

括弧や波括弧を見ると、一般的な「ブロック」という一語でまとめたくなります。Vaak では、次の三つを
別々に数えます。

| 機構 | 何を決めるか |
|---|---|
| 領域 | 外へ見せる値を一つにする |
| スコープ | 名前が見える範囲を決める |
| 脱出段 | `break` と `continue` が一段として数える単位 |

代表的な構文は次の組み合わせです。

| 構文 | 領域 | スコープ | 脱出段 |
|---|:---:|:---:|:---:|
| `( ... )` | ○ | × | × |
| 裸の `{ ... }` | ○ | ○ | ○ |
| 演算子の被演算子 | ○ | × | × |
| `if` の各分岐 | ○ | × | × |
| `switch` の各腕 | ○ | × | × |
| ループ本体 | ○ | ○ | ○ |
| 関数本体 | ○ | ○ | ○、かつフレーム |

括弧 `( ... )` は値の境界だけを作ります。局所変数を宣言する場所にも、`break` の新しい行き先にも
なりません。裸の `{ ... }` は三つすべてを作ります。

```vaak
loop { break; };          % loop の段を抜ける
loop { { break; }; };     % 内側の裸ブロックだけを抜ける
```

ループ本体の `{}` は、ループ構文が持つ一段そのものです。波括弧がさらに一段を重ねるわけでは
ありません。裸のブロックとしてもう一組書いた場合だけ段が増えます。

`if` の分岐に普段 `{}` を書かない規約も、見た目の好みではありません。波括弧を足すと脱出先が
一段変わるためです。

```vaak
loop {
    if (done) break; fi;          % loop を抜ける
};

loop {
    if (done) { break; } fi;      % 裸ブロックを抜けるだけ
};
```

## 6. 脱出は値でも状態でもない

`break`、`continue`、`outward` と作用素式による脱出は、paradox とは別です。脱出は値ではなく、
制御の転送です。そのため `??` では捕まえられません。

```vaak
(break) ?? 42             % `??` が値を待つ場所を、脱出は突き抜ける
```

`break` と `continue` は、どちらも段を進めますが、進めた先での働きが逆です。

| 脱出 | 段に対する働き | 被演算子 |
|---|---|---|
| `break` | その段を終結させる | その場で評価し、値または次の脱出を運べる |
| `continue` | ループ段を次の周回として再開する | 値は運べず、次の脱出は再開点まで遅延する |

`break 5` は「一段を終結させ、その段へ 5 を置く」です。数字 5 は段数ではありません。段数は
`break` を並べることで表します。

```vaak
break 5                % 一段、積み荷は 5
break break 5          % 二段、積み荷は 5
$repeat(break, n) 5    % n 段
```

この構文では、段送りと積み荷が字面で別れています。`$repeat` の回数が 0 以下なら作用素を一つも
重ねず、被演算子がそのまま残ります。

### ループは反復回数を産む

正常に終わった `while` と `nfor` は、最後の本体の値ではなく反復回数を産みます。そもそも本体には
値を残せません。

```vaak
let rounds := while (condition) { step(); };
```

0 周なら、一度も値が生まれず paradox です。`break value` で終わった場合は、反復回数の代わりに
その値が段の結果になります。回数を使わない通常のループでは、ループ全体へ `;` を付けます。

### フレームと `outward`

関数本体と最上位はフレームです。通常の脱出はフレームで止まり、そこを越えようとすると制御エラー
になります。`outward` は、特定の `break` に「このフレームを越えてよい」と明示するための高度な
機構です。

一つの `outward` が越えるのは一フレームだけです。呼び出し側の段数を静的に知れないため、
`outward` の後には定数個の `break` と `continue` だけを書けます。通常の関数内早期 return は、
現在の深さを字句的に畳める次の作用素式で足ります。

```vaak
flow $return = $repeat(break, getdepth());
```

## 7. コピー、セル、別名、権限

値の関係を読むときは、「名前が値そのものか」ではなく、「名前がどのセルを指しているか」を考えると
整理できます。

```text
名前 ──→ セル ──→ 値
```

`:=` は値をセルへ深く複製します。`&=` は名前の矢印を既存のセルへ向けます。

```vaak
var a := [1, 2];
var b := a;                       % 新しいセル、新しい配列
var c : i64 array alias &= a;     % a と同じセル
```

```text
a ──→ セル A ──→ [1, 2]
b ──→ セル B ──→ [1, 2]
c ─────────────→ セル A
```

この模型では、権限も名前の性質として読めます。

- `var` は、その名前からセルへ書けます。
- `let` は、その名前からセルを読めますが書けません。
- `const` は、その名前だけでなく、同じセルへ届くすべての名前からの書き込みを一時的に止めます。

別名が値の内部へ入らず、関数から外へ返らず、再帰的な値グラフを作れないため、領域を抜けるときに
メモリを領域単位でまとめて解放できます。個々の値のデストラクタ、GC、参照カウントはありません。

「複製は深い」「アクセスは複製しない」も、この模型で分けられます。`a[i]` や `p.x` はセルの
中の場所へ到達するだけです。そこから `let x := a[i];` と束縛するときに値が複製されます。

## 8. Akasha という名称

設計記録では、値が何も置かれていない内界面を **akasha / Akasha / アーカーシャ** と呼びます。
実装にも `Eval::Akasha` という名前が残っています。語はサンスクリットの **आकाश**
（ākāśa）に由来し、このリポジトリでは「虚無」や「虚空」の像に結び付けられています。

ただし、Akasha は Vaak の表面構文ではありません。

- `akasha` というリテラルや予約語はありません。
- 利用者が型注釈に書く名前でもありません。
- Akasha を値として関数へ渡すことはできません。
- コード上では、結果を残さないことと `;` の働きによって現れます。

人間向けの説明で「何も無い」と書くのは、特殊な値が一個あるように誤解させないためです。
Akasha という名前は、内界面の空白を指す設計上の呼び名として読むのが適切です。

言語名を検討した初期には、プラトン『ティマイオス』の「場」を指す **Chora**、ākāśa の漢訳に
由来する **Xukong** も候補でした。どちらも中核概念を直接名指す名前でしたが、最終的には意味論を
狭く約束しない `Vaak` が選ばれました。

## 9. Vaak / वाक् の語源

**Vaak** はサンスクリットの **वाक्**（vāk、ヴァーク）に由来し、このリポジトリでは
「言葉」「発話」と説明されています。

名前が名指すのは「領域」や「paradox」という特定の機構ではなく、言語が語るものであるという
一般的な性質です。特定の意味論を名前だけで示唆し、後の設計変更で嘘にしないための選択でも
あります。

```text
REod   ── 言語の当時の性質を名指す
Chora  ── 中核概念である領域を名指す
Vaak   ── 語ること、言語であること一般を名指す
```

`V4k` という綴りも検討されましたが、4K を連想させ、注記なしに「ヴァーク」と読めないため退けられ
ました。現在のファイル拡張子は `.vaak` です。

## 10. REod から Vaak へ

REod は Vaak の前身で、現在は [`legacy/reod-tier1`](../legacy/reod-tier1/) に凍結されています。
REod という名前は `read`、`Runtime Error`、面食らう構文という、当時の言語の性質を示唆して
いました。設計変更によってそのうち二つが当てはまらなくなり、名前も改められました。

Vaak は REod の単なる改名版ではありません。同じ要求を満たすために、意味論を組み直した後継です。
主な要求は次のとおりです。

- ホストの起動ごとに使えるほど起動が速いこと
- JIT が温まる前に終わる短命な処理で速いこと
- そのために、素朴で根本的な表現能力へ絞ること
- TeX 専用に閉じず、やや汎用的であること
- 低い優先度ながら AOT コンパイル可能な意味論であること

REod から引き継いだ重要なものには、領域、Akasha、paradox、`;`、後置の型修飾、作用素式と
動的段数の脱出があります。一方、次のものは要求や読みやすさに照らして捨てられました。

- 動的スコープ
- 既定の遅延評価
- 同じ波括弧へ複数の逆向きの意味を持たせること
- 跳び越した壊れた字句列を解析しなくてよい仕組み
- `goto`、`comefrom`、`label` による任意跳躍

REod を捨てる直接の契機は、短命なホスト処理に必要な素の解釈性能を満たせなかったことです。
起動の速さは定数の利点ですが、遅いループの費用は反復ごとに積み上がります。Vaak は字句スコープ、
先行評価、AST を持つ実装へ移り、参照実装、バイトコード VM、LLVM IR への翻訳を同じ意味論へ
合わせています。

したがって、`legacy/reod-tier1` は歴史と却下理由を読む資料であって、現在の Vaak の仕様では
ありません。REod のコードや文書から、現行構文を推測しないでください。

## 11. 設計を読むときの補助線

このリポジトリには、役割の異なる文書と実装が並んでいます。読み順を分けると混乱しません。

### 実際に書く

1. [人間向けリファレンス](reference.md)
2. [動く六つの例](../examples/vaak/README.md)
3. エディタの診断と補完

例は説明用の擬似コードではなく、参照実装と VM の双方で試験されています。

### 「何がそうであるか」を確かめる

[probe.md](vaak/probe.md) は理由を外して、意味論、構文、組み合わせた結果をまとめた文書です。
純粋な反論を得るため、そこには決定理由を書かないという規律があります。

式の結合については [16-形式構文.md](vaak/16-形式構文.md) の束縛力表が一次資料です。BNF は
「どの固定形があるか」を述べる従属資料で、結合規則を別に実装するものではありません。

### 「なぜそうしたか」を確かめる

[decisions.md](vaak/decisions.md) が決定の唯一の記録です。

- `C-n` は依頼者の承認を経た決定です。
- `S-n` は実装を進める担い手が決め、記録した部分です。
- 後の決定が前の決定を訂正していることがあります。見出しだけでなく、引用する番号そのものを
  読んでください。
- 却下された案と、いったん入れて撤回した経緯も消されません。古い案が残っていることと、現行仕様
  であることを混同しないでください。

`docs/vaak/1x-*.md` は構文を詰めた提案文書です。説明が詳しくても、それ自体は決定ではありません。

### 実装の基準を確かめる

意味論の参照実装は [`src/interp.rs`](../src/interp.rs) です。
[`src/vm.rs`](../src/vm.rs) のバイトコード VM と [`src/steel.rs`](../src/steel.rs) の LLVM IR
生成器が食い違った場合、木を辿る参照実装に合わせます。

ただし、実装されている範囲はバックエンドごとに違います。STEEL は未対応機能を拒否する部分実装で、
`f80` は逆に STEEL 方言だけが持ちます。現在の対応表は
[リファレンスの「ツールと実装範囲」](reference.md#9-ツールと実装範囲)を参照してください。

### PHECL との距離

[`PHECL.md`](PHECL.md) は教育用言語についての原則で、Vaak の上位仕様ではありません。
Vaak は「処理順序を隠さない」「異なる処理を同じ構文へ押し込まない」といった点で、メンタルモデルの
参考として使います。起動速度や短命なホスト上での性能という Vaak の要求と衝突する場合は、衝突を
記録した上で Vaak の要求が優先されます。

## 12. 最小の用語集

| 用語 | 一文で言うと |
|---|---|
| 領域 | 外へ高々一つの値を見せる評価単位 |
| 内界面 | 領域の内側から結果を置く面 |
| 外界面 | 閉じた領域を外から一つの結果として見る面 |
| Akasha | 内界面に値が何も無いこと。値でも型でもない |
| paradox | 外界面で値を要求したが値が無い側 |
| `;` | 結果を捨て、内界面を Akasha にする演算子 |
| `??` | paradox の腕を右辺の値で除く演算子 |
| スコープ | 名前が見える範囲 |
| 脱出段 | `break` / `continue` が一段として数える制御単位 |
| フレーム | 通常の脱出を止める関数本体または最上位 |
| 別名 | 値ではなく、名前を既存セルへ向ける束縛の形 |

これらを一つの「ブロック」「空値」「例外」という既知の語へまとめないことが、Vaak を読み違えない
ための最も短い補助線です。
