# 構文設計 1 — 式と領域の骨格

意味論（[decisions.md](decisions.md) C-1〜C-30）から形を起こす。
**規定は最小に留め、導出できるものは導出する。**

---

## 1. リテラル

### 整数

```
42
1_000_000
0x2A
0b1010
0o17
```

- 底の接頭辞は `0x` / `0b` / `0o`
- `_` は桁区切り。位置は問わない。先頭には置けない
- **型の接尾辞は無い**（`42u8` のような形）

**接尾辞を持たない理由**：型の集合はホスト方言に開いている（C-25）。
字句解析器が知らない型名が出てくるので、接尾辞は破綻する。
型は注釈が与える——`5 -> u8`、`let x : u8 := 5;`。

### 浮動小数

```
3.14
1.5e-3
1e10
.5        ← 認めない。小数点の前に数字が要る
```

### 文字列

```
"hello"
"改行を含む\n"
"\\ \" \0 \x41 \u{3042}"
```

`u8` 配列である（C-7）。`\u{…}` は UTF-8 の並びに展開される。
**言語は文字を知らない**ので、`\u{…}` は「この符号位置の UTF-8 表現」という字句上の略記でしかない。

### リテラルはソースの表現を保持する

C-25 の要求。`0.1` を字句解析の時点で `f64` にすると、`f80` へ広げても精度は戻らない。
**型が決まる地点まで、リテラルはソースの文字列として保持される。**

### 注釈が無いときの既定型

**規定である。導出ではない。**

| | 既定 |
|---|---|
| 整数リテラル | `i64` |
| 浮動小数リテラル | `f64` |

標準実装は型検査をしない（C-18）ので、注釈が無ければ何かに決めるしかない。

## 2. ブロック

```
{ 文; 文; 末尾式 }
```

`{ }` は**領域・スコープ・脱出段の三つを同時に作る**（C-20 まで）。それ以外の用途に使わない。

- 中身は `;` で区切られた列と、任意の末尾式
- 末尾式があれば、それが内界面に置かれる値
- 末尾式が無ければ内界面はアーカーシャ

### 文として使うときは `;` を付ける

```
{ E; };
```

末尾式の無いブロックの値は paradox である（規則2）。**そのまま置けばエラーになる**（C-22）ので、
`;` で潰す。**`;` は飾りではなく、paradox の消費である。**

---

## 3. `;`

**最低優先順位の後置演算子。** 左の値を評価してからアーカーシャへ潰す。

- 「文の終わり」ではない。**値を消す演算子**である
- したがって置き場所を規則として覚える必要が無い。**値を消したいところに書く**
- paradox も潰せる（C-14 規則3）

---

## 4. 演算子と優先順位

強く結合する順。

| | 演算子 | |
|---|---|---|
| 1 | `f(…)` `a[i]` `x.m` `x.m(…)` | 後置 |
| 2 | `-` `!` | 前置 |
| 3 | `*` `/` `mod` | |
| 4 | **`??`** | **C-27** |
| 5 | `+` `-` | |
| 6 | `<<` `>>` | |
| 7 | `&` | |
| 8 | `^` | |
| 9 | `\|` | |
| 10 | `<` `<=` `>` `>=` `==` `!=` | `u1` を返す |
| 11 | `&&` | 短絡 |
| 12 | `\|\|` | 短絡 |
| 13 | `\|>` | |
| 14 | `;` | 最低 |

### `??` が乗除の次である理由

paradox を産む構文がすべて `??` より強く結合する（C-27）。

```
5 / 0 ?? d        →  (5 / 0) ?? d
a + b / c ?? d    →  a + ((b / c) ?? d)
arr[i] ?? d       →  後置なので (arr[i]) ?? d
```

**括弧を書かずに、除去が導入点の直近で起きる。**

### ビット演算が比較より強い

C の有名な誤り（`a & b == c` が `a & (b == c)` になる）を踏まない。
`a & b == c` は `(a & b) == c` と読まれる。

### `!` は全ビット反転である

**論理否定と別に持たない。** `u1` は1ビットなので、全ビット反転がそのまま論理否定になる。
**一つの演算子、一つの意味**（PHECL 原則6）。

### `&&` と `&` は別の操作である

`u1` に対して同じ値を返すが、**`&&` は右辺を評価しないことがある。**
何が走るかが違うので、§1.2 の観点から別の操作である。両方持つ。

## 5. `??`

```
E ?? D
```

E の領域が paradox を持って終結したとき、**終結を撤回して** D を置く（C-14、C-27）。

- E が paradox でなければ E の値
- **`??` だけが終結を撤回できる。例外は無い**
- 連鎖できる：`a ?? b ?? c`（**右結合**。非対称な優先順位の帰結、C-45）

```
a ?? b; ?? c      →  c
```

`;` がアーカーシャにするので、その後の `??` は必ず発火する（C-26）。

## 6. `|>`

```
x |> f(a)        ≡  f(x, a)
x |> f()         ≡  f(x)
x |> f() |> g()  ≡  g(f(x))
```

**構文の水準の糖衣**（C-15）。第一級関数を要求しない。

`|>` は**自由関数に適用する**。`x` の型の名前空間を探しに行かない——
探すなら `.` を書く（C-15 の境界規定）。

優先順位が低いので、左に式全体を置ける。

```
a + b |> f()     →  (a + b) |> f()
```

---

## 7. 括弧

```
( E )
```

**領域を作るが、スコープも脱出段も作らない。** 優先順位を変えるためだけのもの。

`{ E }` との違いは重要である——`{ }` は三つ全部を作る。
**「囲みたいだけ」なら `( )` を使う。**

## 最上位（C-31 で決定）

プログラム全体の領域は終端するが、**その外界面は Vaak の意味論ではない。**

```
x := 1;
y := 2;
```

内界面がアーカーシャで終わるプログラムは**エラーではない。** 解釈はホストに委ねる。
**POSIX Vaak では `exit 0`。**

末尾に値を置けば、その値がホストへ渡る。

```
x := 1;
y := 2;
x + y        ← ホストはこの値を受け取る
```

**paradox がホストに届くことはない**——生まれた領域で終結してエラーになるので（C-22）。
エラーの報告（発生点）は、プログラムの値とは別の経路である。
