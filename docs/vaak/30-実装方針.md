# Vaak 実装方針

**決定は [decisions.md](decisions.md)（C-1 〜 C-90）。構文は [16-形式構文.md](16-形式構文.md)。**
**進捗は リポジトリ直下の [PROGRESS.md](../../PROGRESS.md) に書く。**

## 1. 何を作るか

**木を辿るインタプリタと、独立した静的検査器。** バイトコード VM は後。

理由：**意味論が特殊なので、まず参照実装が要る。**
後で VM を書いたとき、**両者を同じテストに掛けて差分を取る**のが唯一の検証手段になる。

```
source
  ↓  lexer
tokens
  ↓  parser（Pratt。束縛力表が一次仕様）
AST
  ↓  resolve（名前解決・宣言の収集）
  ↓  check（型・領域・権限・別名・段数）
Checked AST
  ↓  interp（木を辿る）
結果
```

**検査器は独立している**が、**同じ AST を使う**。C-31 の「インタプリタは型を解決するが検査はしない」に従い、
**検査を飛ばしても走る**ようにする（未検査プログラムの挙動は規定しない）。

## 2. 構成

```
src/
  main.rs      CLI。ファイルを読んで走らせる
  lib.rs       公開界面
  span.rs      位置情報
  lexer.rs     字句解析
  ast.rs       AST の定義
  parser.rs    Pratt パーサ
  types.rs     型の表現と逆ポーランド解決
  resolve.rs   名前解決
  check.rs     静的検査
  value.rs     値・セル・アリーナ
  interp.rs    木を辿る評価器
  builtin.rs   標準ライブラリ
  host.rs      ホスト界面
tests/
  lex.rs       字句
  parse.rs     構文（プローブの解析例）
  semantics.rs 意味論（プローブの「この通りに動きます」を全部）
```

## 3. 核となるデータ型

```rust
enum Eval {          // 評価の結果。三分類（C-88）
    Value(Value),
    Paradox(Span),   // 発生点を持つ（C-46）
    Escape(Escape),
}

struct Escape {
    kind: Break | Continue,
    stages: u32,        // 残りの段数
    outward: u32,       // 越えるフレーム数
    payload: Option<Value>,
    deferred: Option<NodeId>,  // continue の遅延被演算子（C-73）
}
```

**`Value` に paradox を入れない**（C-85 (2)：セルは paradox を保持しない）。
**`Escape` を `Value` に入れない**（脱出は値ではない）。

**アリーナ**：領域ごと。抜けたらポインタを戻す（C-90）。
最初の実装は `Vec` のインデックスで代用してよい——**意味論に影響しない。**

## 4. 段階

各段階が終わるたびに **PROGRESS.md を更新して commit する。**

| | 段階 | 完了の条件 |
|---|---|---|
| **P0** | 足場 | `cargo test` が通る空の骨格 |
| **P1** | 字句解析 | プローブの字句節を全部。入れ子コメント、Unicode 識別子 |
| **P2** | AST とパーサ | プローブの解析例（`a; -b` `break 5 ?? 42` 等）が全部正しい木になる |
| **P3** | 値・セル・アリーナ | 深い複製・別名・権限が持てる |
| **P4** | 評価器 | プローブの「この通りに動きます」の**実行時の項**が全部通る |
| **P5** | 静的検査器 | 同じく**静的エラーの項**が全部通る |
| **P6** | 標準ライブラリ | `$return` `.len()` `.push()` `$repeat` `getdepth()` |
| **P7** | ホスト界面 | `&=` でホストのメモリに張れる |
| **P8** | 意味論テスト | プローブの全項目がテストになっている |
| **P9** | バイトコード VM | P4 と差分が出ない |

**P4 まで来れば言語が動く。** P5 は独立に足せる。

## 5. 実装で気をつけること（決定から）

| | |
|---|---|
| 解析器は `min_bp` のほかに **`has_value`** を持つ（C-85 (4)） |
| `;` は左辺の**領域**を要求する。空でもよい（C-80） |
| `??` の除外は**旗**。束縛力では書けない |
| 腕は `E@6`、分岐は `E@0`（C-82 / C-68） |
| **段送りは左から右**（C-70） |
| **`break` の被演算子は即時、`continue` は遅延**（C-73） |
| **`continue` の被演算子は本体の先頭のスコープで名前解決**（C-81） |
| **`{ }` が段を作るのは裸のときだけ。** ループ／関数の本体はその構文の段（C-64） |
| **paradox は消費されずに値の要求に出会ったときエラー**（C-88 (1)） |
| **別名の判定は名前の比較。レシーバも数える**（C-87 / C-89） |
| **浮動小数は各演算の後に `is_finite()`**（C-84） |
| **除算はユークリッド。整数は 2^N を法とする**（C-76 / C-79 (3)） |

## 6. テストの作り方

**プローブの「この通りに動きます」が仕様書である。**
各行を一つのテストにする。**期待値が書いてあるので、そのまま移せる。**

```rust
#[test] fn 領域に値が二つ() { static_error("{ a b }"); }
#[test] fn 空の領域は_paradox() { assert_paradox("{ }"); }
```

**P9 で VM を書いたら、同じテストを両方に掛ける。**
