# 構文設計 5 — 型と集合体

意味論は C-6 / C-7 / C-8 / C-11 / C-19 / C-20 / C-21 / C-25 / C-30 / C-33 / C-35。

---

## 1. 型の書き方

**完全後置修飾。** 基底型に修飾子を後ろから重ねる。

```
i64                  基底型
i64 array            i64 の配列
i64 alias            i64 への別名
i64 array alias      i64 の配列への別名
i64 alias array      i64 への別名の配列
str i64 map          str から i64 への写像
```

**読む順序が書く順序と一致する。** `Map<Str, I64>` のように内から外へ読み返さない。

### 修飾子は閉じた集合である

| 修飾子 | 取る型の数 |
|---|---|
| `array` | 1 |
| `alias` | 1 |
| `map` | **2**（鍵、値の順） |

**それぞれの引数の数が決まっているので、括弧が要らない。**
`str i64 map` は「str、i64、写像」であり、**鍵が先、値が後**である。
これは `=>` の向き（`鍵 => 値`）と一致する。

修飾子が閉じた集合であることは規定である。**開いていれば括弧が要る。**

### 基底型

| | |
|---|---|
| 整数 | `u1` `u8` `u16` `u32` `i32` `i64` |
| 浮動小数 | `f32` `f64` |
| 別名 | `str`（= `u8 array`、C-7） |
| ユーザ定義 | 構造体の名前 |

**ホスト方言が基底型を足せる**（`i63`、`f80` 等、C-25）。修飾子の集合は足せない。

## 2. 配列

```
var a : i64 array := i64 array ( 10, 0 );

a[0] := 5;
let x := a[0];
let n := a.len();
```

- `[]` は**アクセス**であり、複製しない（C-20）
- `a[i]` の結果を束縛すれば、そこで複製される
- **範囲外の添字は paradox を産む**（C-22）

```
let x := a[i] ?? 0;
```

**言語が知る列は配列だけ**である（C-8）。反復子は無い。

```
nfor (i, 0, a.len()) { … };
```

---

## 3. 文字列

**`u8 array` の別名**（C-7）。**言語は文字を知らない。**

```
let s : str := "hello";
let b := s[0];              104。バイトである
let n := s.len();           バイト数である
```

UTF-8 の解釈——符号位置の切り出し、文字数、境界——は
**無名標準ライブラリのメソッド**が提供する。何を「1文字」と数えているかが**名前に現れる。**

```
s.codepoint_count()
s.codepoint_at(i)
```

## 4. 連想配列

```
var m : str i64 map := ( "a" => 1, "b" => 2 );

let v := m["a"] ?? 0;
m["c"] := 3;
```

- **欠損キーは paradox を産む**（C-22）。`??` が受ける
- リテラルは `( 鍵 => 値, … )`

### リテラルは一つの領域に一つの値である

`( "a" => 1, "b" => 2 )` は**一つの写像**という値を持つ一つの領域である。
`( )` に第二の意味を与えていない。

**有限写像は関数である。** この記法は**無名の有限関数**を書いていることになる。
そして適用は添字である。

```
( 1 => "one", 2 => "two" )[n] ?? "many"
```

### `,` の役割

**引数列の `,` と同じである**——区切りであって演算子ではない。
`f(a, b)` の `,` も `( "a" => 1, "b" => 2 )` の `,` も、**並べるための記号**である。

`=>` は**対を作る演算子**であり、`switch` の腕と同じ記号を使う（C-39）。
どちらも「これをこれに対応させる」を意味する。

## 5. 構造体

```
struct Point {
    var x : i64 := 0;
    var y : i64 := 0;
};
```

**本体はブロックである。** `{ }` に第二の意味を与えていない——
**欄の宣言が並ぶスコープ**であり、各宣言が paradox を産み、外側の `;` が潰す（C-40）。

- 欄は宣言なので、`var` / `let` / `const` が使える。**欄ごとの可変性がそのまま書ける**
- `:= E` は**既定値**である。省略できる

```
struct Config {
    let name : str;              既定値なし。構築時に与える
    var retries : i64 := 3;      既定値あり
};
```

### 構築

**`型 ( 引数 )` が構築式である**（C-52）。欄は名前で与える。

```
let p := Point ( x := 1, y := 2 );
let c := Config ( name := "a" );        既定値のある欄は省略できる
```

**構築はプリミティブである。** 標準ライブラリに構築子は要らない——
欄を持つ値を作る手段が言語に無ければ、標準ライブラリも書けないので（循環する）。

そして `:=` の意味がそのまま効く——**新しいセルを作って初期値を書く**。

### 欄へのアクセス

```
p.x := 5;
let y := p.y;
```

`.` は**アクセス**であり複製しない（C-20）。

## 6. メンバ関数

```
fn Point.norm2 (self) {
    self.x * self.x + self.y * self.y
} -> i64;

fn Point.scale (var self, k : i64) {
    self.x *= k;
    self.y *= k;
};
```

- 名前は `型.関数名`。**型の名前空間に入る**
- 第一引数 `self` が**レシーバ**。型は `T alias` である（`.` は複製しないので、C-20）
- **束縛種の既定は `let`**（C-40）。書き換えるなら `var self` と書く

### 破壊が署名に出る

```
fn Point.norm2 (self)          読むだけ
fn Point.scale (var self, …)   書き換える
```

C-20 は「破壊は呼び出し側から見えない。規約で補う」とした。
**宣言の側では見える。** `var self` が印になる。

呼び出し側では依然として見えないので、**規約は残る**——
> **メンバ関数の名前は、レシーバを破壊するかどうかを示さねばならない。**

### 同じ名前は同じ意味を持たねばならない（規約、C-11）

`.len()` が「要素数」なら、どの型でも要素数である。
バイト数を返す型と要素数を返す型が同じ名前を使ってはならない。

**処理系は検査できない。** 規約として書き、レビューで守る。

## 7. 例

```
struct Point {
    var x : i64 := 0;
    var y : i64 := 0;
};

fn Point.norm2 (self) {
    self.x * self.x + self.y * self.y
} -> i64;

fn Point.dist2 (self, other : Point alias) {
    let dx := self.x - other.x, dy := self.y - other.y;
    dx * dx + dy * dy
} -> i64;

fn nearest (ps : Point array alias, q : Point alias) {
    var best := 0, best_d := ps[0].dist2(q);
    nfor (i, 1, ps.len() - 1) {
        let d := ps[i].dist2(q);
        if (d < best_d) { best := i; best_d := d; } fi;
    }
    best
} -> i64;
```

## 決着した細部（C-41）

- **構造体の宣言語は `struct`。** `type` は将来の型別名のために空けておく
- **返り値型は省略できる。** `fn f (…) { … };`。空の型を書かせる形は採らない
