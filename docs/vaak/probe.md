埋め込み用インタプリタ言語の意味論と構文です。
まず批判的に吟味してください。そのうえで実装の LOC を見積もってください。

# 最初に：三つを混同しないでください

この言語には、他の言語で一つにまとめられがちなものが**三つ別々に**あります。

| | | |
|---|---|---|
| **何も無い** | **値ではない。** 領域を占めない | `void` でも `unit` でも `null` でもない |
| **paradox** | **値だが、`;` と `??` 以外の演算子は受け付けない。** 領域の外側から見える | `f(1/0)` は関数に届かない。引数の領域が paradox で終結した時点でエラー |
| **脱出** | **値でも状態でもない。** 制御の転送 | `??` はこれを捕まえられない |

**「何も無い」と paradox は別物です。** 領域の中身が「何も無い」とき、
その領域を**外から見た値**が paradox になります。中身と外から見た姿が違う、ということです。

**単位型（unit）はありません。** 「何も返さない関数」は unit を返すのではなく、
中身に何も残らないので**外から見ると paradox** です。

## そして、すべての型は paradox との直和です

**`i64` 型の式は、`i64` か paradox のどちらかを外界面に置きます。**
別の型ではありません——**`Option` も `Maybe` も無く、包む操作もありません。**

**ただし、これは領域の外界面の話です。セルは paradox を保持しません。**
**式の型は `T ⊕ paradox`、セルの型は `T` だけ**——
だから束縛の前に `??` で落とさねばなりません。

**`??` はその直和の除去子です。** 左の paradox 側を落として、右で埋める。

```
fn find (a : i64 array alias, x : i64) { … } -> i64;

let pos := find(xs, 42) ?? -1;     ?? が paradox の腕を落とす
let pos := find(xs, 42);           見つからなければエラー。セルは paradox を保持できない
```

**したがって `->` は「外界面の型」です。** 正常終了時の型ではありません。

| | 外界面の型 |
|---|---|
| `-> i64` | **`i64` ⊕ paradox** |
| `->` が無い | **paradox のみ** |

```
fn f () { if (c) break 42 fi; };        エラー。paradox しか取らない外界面に 42 を置いた
fn f () { if (c) break 42 fi; } -> i64; よい。c が偽なら paradox
fn f () { 1; } -> i64;                  通る。常に paradox を返す。無意味だが型は正しい
```

**脱出で置いた値も、正常終了で置いた値も、同じ外界面に置かれます。** 区別しません。

# 意味論

## 領域

- 「領域」は**値を持つ単位**。一つの領域は値を一つしか持てない
- **内面**（中身）と**外界面**（外から見える値）を区別する
- 領域は終結した時点で外界面の値を持つ
- **内面に何も残っていない**か、**内面に置かれた値が paradox** なら、**外界面は paradox**
- paradox を受け付ける演算子は **`;` と `??` の二つだけ**。
  `;` は潰し（内面を空にする）、`??` は消す（値に置き換える）
- **領域が paradox を持って終結したら、その時点でエラー**
- **終結を撤回できるのは `??` だけ**

**終結は二段階ある**——`??` の前に起きるものと、後に起きるもの。
`??` が介入できるのはその間だけ。

したがって `( break ) ?? 42` は無効である——**`??` は値に作用する演算子であり、脱出は値ではない。**

**評価と実行を区別する。**
「評価」は式が自分の領域で値になること、「実行」は外界面に置かれた作用が起きること。

**脱出は段を一つ進める。被演算子は外界面で処理される。**
そして**外界面がどこかは、脱出の種類で違う。**

| | 外界面 | スコープ | 被演算子 |
|---|---|---|---|
| `break` | **段の外** | **死んでいる** | **即時に評価される** |
| `continue` | **再開した本体の先頭** | **生きている** | **即時に評価されない** |

```
{{ let x := 2; break break x }}          2。break なので x はここで読まれる
nfor (i, 0, 10) { continue break i; }    1。continue が break i ごと次の周回へ送る
```

**`continue` で即時に読むと、前の周回の値を次の周回に持ち込む。** それは周回の意味を壊す。

領域・スコープ・脱出段は別の概念:

| | 領域 | スコープ | 脱出段 |
|---|---|---|---|
| `( E )` | ○ | × | × |
| **裸の**ブロック `{ E … }` | ○ | ○ | ○ |
| 演算子の被演算子位置 | ○ | × | × |
| `if` の分岐 | ○ | × | × |
| `switch` の腕 | ○ | × | × |
| ループ本体 | ○ | ○ | ○ |
| 関数本体 | ○ | ○ | ○（**フレーム**） |

**`{ }` が段を作るのは、それ自体が式として置かれたときだけです。**
`loop` / `while` / `nfor` / `fn` の本体は**その構文の段**であって、**二重にはなりません。**

```
loop { break; };          ループを抜ける。段は一つ
loop { { break; }; };     裸のブロックを抜けるだけ。段は二つ
```

## 領域の中で式がどう並ぶか

**文と式の区別はありません。** `;` は最低優先順位の後置演算子で、
左の値を評価してから潰し、内面を空にします。

**`;` は常に左辺に領域を要求します。その領域が空でも構いません**——
空なら値は paradox であり、`;` がそれを潰します。`{ ; }` も `1;;` も通ります。

```
{ a; b; c }        a と b は潰れる。内面に c が残る。外界面は c の値
{ a; b; c; }       全部潰れる。内面が空 → 外界面は paradox
{ a b }            エラー。一つの領域に値が二つ
{ }                内面が空 → 外界面は paradox
```

**式を並べても値は連鎖しません。** 各式は自分の領域に値を置き、
`;` が無ければ同じ領域に二つ置かれてエラーになります。

**代入は値を置きません。外界面は paradox です。** 宣言と同じ形なので `;` が要ります。

```
x := 5;                 ; が代入の paradox を潰す
while (m) { m /= 10; }  本体に何も残らない
(x := 5) + 3            エラー。+ が paradox を受け付けない
```

**数えるのは正常に続く経路だけです。脱出する経路は値を置きません。**

```
loop { if (c) continue; fi; 1; }      通る
loop { if (c) break else 2 fi }       エラー。else が値を残す
loop { if (c) break else 2; fi }      エラー。if の paradox が残る
loop { if (c) break else 2 fi; }      通る。fi の後の ; が潰す
if (c) 1 else 2 fi                    どちらも値を置く。一つの領域に一つ
```

したがって静的検査は、**式が値を置くか・paradox を置くか・脱出するか**を追います。

## 評価と束縛

- 先行評価、字句スコープ。**クロージャ・第一級関数・高階関数は無い**
- **評価されるものは左から右に評価する**（短絡する `&&` `||` `??` は右を評価しないことがある）。
  代入は**左辺の場所を先に解決してから**右辺を評価する
- **関数本体から見えるのは、引数・自身のスコープの宣言・そして**
  **囲むスコープの `fn` / `struct` / `flow` 宣言だけ。**
  **局所変数（`var` / `let` / `const`）は、どのスコープのものも見えない**
- **`fn` / `struct` / `flow` の宣言はスコープ全体で見える**（前方宣言は無い）。変数は宣言位置から先
- **宣言はスコープを作る領域にしか置けない**——ブロック・ループ本体・関数本体・最上位。
  `( )` にも `if` の分岐にも `switch` の腕にも置けない。
  **宣言は名前をスコープに入れる操作なので、入れる先が要る**
- **非 alias の引数は深く複製する。** `fn f (var a : i64)` の `a` は呼び出し側と別のセル
- `:=` は**この名前が指すセルに値を書く**（複製する）
- `&=` は**この名前が別のセルを指すようにする**。ホストのメモリにも張れる
- **複製は深い。** 部分的な浅さは無い
- **`.` と `[]` はアクセスであり複製しない。束縛が複製する**
- メンバ関数のレシーバは複製されない。**破壊的である。**
  したがって**破壊的メンバ関数はレシーバに `var` を要求する**——`let a := …; a.push(1);` はエラー
- 束縛種は三つ:
  - `var` — この名前から書ける
  - `let` — この名前から書けない
  - `const` — **そのセルが誰からも書けない**。スコープを抜けると解ける。
    **`const b &= a;` は `a` からの書き込みも禁じる**——「誰からも」は字義どおり。
    同じセルに `const` 別名が複数あれば、**すべてのスコープを抜けるまで解けない**
- **別名は値ではない。束縛の形態である。** `alias` は型注釈の最も外側にのみ書ける
- **`&=` の対象は名前だけ。** `&= a[i]` も `&= p.x` も書けない——
  **束縛は呼び出しより長く生きるので、`.push()` で再確保されると壊れる**
- **メンバ関数のレシーバは経路でよい。** `arr[0].push(3)` は書ける——
  **レシーバは呼び出しより長く生きない**
- **`alias` を受ける引数に渡せるのは名前だけ。**
  そして**同じ呼び出しで、同じセルに届く別名を二つ以上渡せない**——
  `f(arr[0], arr)` も `f(p, p)` も書けない
- **`alias` の束縛は `&=` に限る。** `var y : T alias := x;` はエラー
- **別名は指し直せる**（`b &= c`）。**`var` の別名にだけ許され**、
  指す先の検査は宣言時と同じ。**`b := c` はセルに書き、`b &= c` は名前を動かす**
- **別名は内へは渡せるが、外へは返せない。**
  関数に渡すのは外側のスコープを指すのでよい。返すのは内側を指すのでエラー
- **経路の権限は増やせない**（`let` から `var` 別名は作れない）。
  **凍結は常に許される**——能力を奪うだけで、与えないから
- **所有の巻き戻し機構は無い**——デストラクタも解放処理も走らない。所有は完全に字句的。
  **GC も参照カウントも無い。** だから段を何段進めても、フレームを越えても、片付けるものが無い

## 型

- 基底型は `u1 u8 u16 u32 i32 i64 f32 f64`。
  そこに**配列 `array`・写像 `map`・構造体・ラップ型**が積み重なる。
- **`str` は `u8 array` をラップした型。言語は文字を知らない**——
  添字はバイトを返し、長さはバイト数。UTF-8 の解釈は標準ライブラリが提供する。
  **NUL 終端を持たない**
- **配列のメソッドは `str` に直接効く**（`.len()` `.push()` `[]`）。
  **文字列リテラルの型は `str`**
- **包むのも剥がすのも `new`。** どちらも構築なので**深く複製する**——費用が字面に出る
  - `new str ( bytes )` / `new u8 array ( s )`
- **利用者もラップ型を宣言できる**（`str` は特例ではない）
- **`u1` が真偽値**
- **構築は `new 型 ( 引数 )`。** 構造体の欄は名前で与える。
  `new Point ( x := 1, y := 2 )` / `new i64 array ( 10, 0 )` / `new str i64 map ( )`
- **配列は動的**（`.push` などで伸びる）。配列リテラル `[ 1, 2, 3 ]`
- 型は**逆ポーランド記法**。修飾子は引数の数が決まった後置演算子
  - `array` は 1 つ取る、`map` は 2 つ取る（**鍵、値の順**）
  - 左から積み、**最後にちょうど一つの型が残らねばならない**
  - `i64 array` / `str i64 map` / `str i64 array map`
- `alias` は修飾子ではない。**束縛の形態**なので最も外側にのみ置ける
- `:` は識別子に、`->` は領域に付く
- **構造体の型依存グラフは DAG でなければならない。** `struct Node { var next : Node; }` はエラー。
  別名は値の中に入らないので、**再帰的なデータ構造は作れない**——添字で表す
- **暗黙の数値変換は無い。** **すべての整数演算は 2^N を法として行う**——
  溢れは二の補数で折り返し、恒等式もその法の上で成り立つ。折り返しは失敗ではない。
  **0 除算は paradox。浮動小数の非有限な結果もすべて paradox**——
  溢れも 0 除算も不定形も。**inf も NaN も、この言語には存在しない**
- **NaN が無いので比較は全順序である。** `==` は同値関係、`a == a` は常に真
- **除算はユークリッド除算。** 余りが `[0, |右辺|)` に入るように商を丸める。
  **恒等式 `a = (a / b) × b + (a mod b)` が常に成り立つ**
- リテラルは**型が決まるまでソースの表現を保持する。型接尾辞は無い**
- 注釈が無ければ整数は `i64`、浮動小数は `f64`
- ホスト方言は**基底型を足せる**（例: 31/63bit 整数、f80）。**修飾子は足せない**
- **インタプリタは型を解決する**（注釈を読んでリテラルの型を決める）が、**検査はしない。**
  標準実装は**検査を通したプログラムを受け取ることを前提とする。**
  通していないプログラムの挙動は規定しない

## 制御

- `if` は演算子。条件は `u1` 一つの領域。**分岐は被演算子位置なので `{}` で書かない**
- `while` の条件は**任意の整数型。`≠ 0` で継続**
- `nfor` の三被演算子は**束縛名・開始・回数**。歩幅は無い。
  束縛名は本体の中で `let` であり、スコープは本体
- **ループが受け取るブロックの中身は、何も残ってはいけない**（静的検査）
- **正常終了したループの値は反復回数。脱出で終わったループの値は脱出が置いた値。**
  0 周なら領域が `{}` になり paradox。値の無い `break` で抜けたループも paradox
- `nfor` の回数が 0 以下なら 0 周。**回数の型は `i64`、`i` の型は開始値の型。**
  `i` の増加は通常の整数演算（溢れれば折り返す）
- `switch` は閉じる語を持たない。**`case` 以外が来た時点で終わる。**
  腕は**上から順に照合**し、**当たった腕の値だけを評価する**
- **段数は反復でのみ表す。** `break break break` で 3 段、`$repeat(break, n)` で n 段（n は実行時の値）。
  **被演算子は段数ではない**——`break 5` は「1 段抜けて 5 を置く」であって「5 段抜ける」ではない
- **`break` 自身の値は paradox。領域を閉じてから脱出が起きる**
- **脱出は三つとも同じ形で、被演算子の種類だけが違う**:

| | 値 | 作用素式 | 虚無 |
|---|:-:|:-:|:-:|
| `break` | ○ | ○ | ○ |
| `continue` | **×** | ○ | ○ |
| `outward` | **×** | ○ | **×** |

  `continue` が値を取れないのは、**周回を次へ進めても値の置き場所が無い**から。
  `continue continue` は有効。`continue 1` はエラー
- **合成は外側の脱出で決まる。** `break X` は**段数を足す**（被演算子が即時なので）。
  `continue X` は**足さない**——X は再開した本体の先頭で実行される
- **`continue` の被演算子から見えるのは、本体の先頭で見えている名前だけ**——
  ループ変数と外側の名前。**本体で宣言された名前は見えない**（まだ束縛されていない）。
  だから**捕獲もクロージャも要らない**
- **段送りは書いた順（左から右）に起きる**
- **`break` は段を終結させる。`continue` は段を再開させる。**
  だから `break continue` は**エラー**——終結した段は再開できない
- `continue` は抜けた先がループでなければ**制御のエラー**
- 脱出は**フレーム（関数本体、または最上位）で止まる**。
  **上限まで抜けるのは許される**——`break` が関数本体を抜ければ関数から返る。
  **越えるのがエラー**
- 越えるには `outward` と書く。**`outward` は被演算子に脱出を要求する**——
  値を置くだけなら `outward` は要らない（`break 42` と同じになる）
- **`outward` は書いた `break` の段送りに掛かる。** 深さ 3 からフレームを越えるなら
  三番目に書く（`break break break outward break 1`）。**空振りの `outward` は静的エラー**
- **`outward` を越えた後の段数に `getdepth()` を使えない**——
  呼ばれた側の深さで呼んだ側の段を数えることになる。**`break outward $return` は書けない。**
  `outward` の後に書けるのは**定数個の `break` と `continue` だけ**である
- **制御構造に名前を与えられる**（値でも関数でもない第三の束縛種）。
  名前は `$` で始まる。**本体は使用位置で読み直される**ので `getdepth()` が使用位置の深さを返す。
  `flow $return = $repeat(break, getdepth());` が標準ライブラリに書かれている
- **`flow` の本体に `flow` 名を書けない**（展開が止まらないので）。
  **スコープ全体で見え、同名の再定義はできない**
- **`$repeat` の第一引数は `break` か `continue` に限る。**
  **`n` が 0 以下なら作用素を一つも重ねない**——被演算子がそのまま残る
- 任意跳躍（goto/label）は無い。**例外機構も無い**
- **`&&` / `||` は短絡する。** `0 && (1 / 0)` は右辺を評価しないので paradox が発生しない
- **`??` は左を右で置き換えるだけ**で、右を検査しない。右が paradox なら全体が paradox
- **脱出は値位置を突き抜ける。** 演算子は適用されず、残りの被演算子も評価されない
- **段数を静的に検査できるのは、脱出が定数個並んでいる場合だけ。**
  `$repeat` の回数が定数でない場合と `outward` を含む場合は**実行時に検査する**
  （`$return` は `getdepth()` が字句的に決まるので静的）
- **`|>` は構文の水準の糖衣。** `x |> f(a)` ≡ `f(x, a)`、`x |> f()` ≡ `f(x)`。
  第一級関数を要求しない。**自由関数に適用する**——`x` の型の名前空間は探さない（探すなら `.`）

## エラー

**実行時エラーは三種だけ**:

| | |
|---|---|
| **値** | 消費されなかった paradox。ホストは**発生点**を受け取る |
| **制御** | フレームを越える脱出 |
| **制御** | **終結した段の再開**（`break continue` / 抜けた先がループでない `continue`）|

**静的エラーは複数ある**——領域に値が複数／ループ本体に値が残る／名前解決／権限／
型構築の引数不足／型依存グラフの循環／比較の連鎖／`alias` 引数に名前以外を渡すこと／
同じ呼び出しで同じセルに別名が二つ届くこと（**異なることを証明できなければエラー**）。
**走らせる前に分かるので、数を絞る必要が無い。**

**無限ループはエラーではない。** 評価結果の第四の分類（発散）である。

paradox を産むもの: 0 除算 / 配列の範囲外 / 写像の欠損キー / 0 周のループ /
`else` の無い `if` で条件が偽 / どの腕にも当たらない `switch` /
剥がされたホスト別名 / **宣言** / **代入** / 空の領域 / **`break` 自身**

最上位の領域の**外界面は言語の意味論ではない**。中身が空で終わればホストに委ねる。

# 構文

**束縛力表が一次仕様。BNF はそれに従属し、結合を語らない。**

## 解析の規則

```
parse(min_bp):
    左辺 := 前置または一次式を読む
    has_value := 真
    繰り返し:
        次の演算子の左束縛力 < min_bp なら止める
        has_value が偽で、その演算子が左辺の値を要求するなら止める
        演算子を消費し、右辺を parse(その演算子の右束縛力) で読む
        `;` を消費したときは has_value := 偽
```

**`has_value` が要る。** `;` は左辺の**領域**を空にするので、その後に値は無い。

```
a; -b       (a;) の後に値が無いので、- は前置。a - b ではない
1;;         ; は領域を要求するので、空でも働く
```

**`;` が「必ず取る」のは領域、`+` `-` が「取れば取る」のは値である。**
空の領域から `;` は paradox を得るが、`-` は何も得ない。

| 演算子 | 位置 | 左束縛力 | 右束縛力 |
|---|---|---:|---:|
| `f(…)` `a[i]` `.m` | 後置 | 90 | — |
| `+` `-` `!` | 前置 | — | 80 |
| `*` `/` `mod` | 中置・左結合 | 70 | 71 |
| **`??`** | **中置** | **60** | **31** |
| `+` `-` | 中置・左結合 | 50 | 51 |
| `<<` `>>` | 中置・左結合 | 45 | 46 |
| `&` | 中置・左結合 | 42 | 43 |
| `^` | 中置・左結合 | 40 | 41 |
| `\|` | 中置・左結合 | 38 | 39 |
| `<` `<=` `>` `>=` `==` `!=` | 中置・非結合 | 30 | 31 |
| `&&` | 中置・左結合 | 25 | 26 |
| `\|\|` | 中置・左結合 | 20 | 21 |
| `\|>` | 中置・左結合 | 15 | 16 |
| **脱出** | **前置** | — | **8** |
| **`:=` `&=` `+=` `-=` `*=` `/=` `mod=` `<<=` `>>=` `^=` `\|=`** | **中置・非結合** | **7** | **6** |
| `;` | 後置 | 5 | — |

**`;` は左辺の式が無くてもよい。** その場合、左辺は空の領域（値は paradox）である。

```
a + b / c ?? d + e     →  a + ((b / c) ?? (d + e))    右 31 < 加減 50
a ?? b ?? c            →  a ?? (b ?? c)               右 31 < 左 60 なので右結合
a ?? b < c             →  (a ?? b) < c                右 31 > 比較 30 なので吸わない
break 5;               →  (break 5);                  脱出 8 > `;` 5
break break break      →  3 段（前置の連鎖）
x := 5;                →  (x := 5);                   代入 7 > `;` 5
break x := 5           →  (break x) := 5              脱出の被演算子は parse(8)
break x + y            →  break (x + y)               + (50) は 8 以上なので吸う
```

**代入は演算子である。** 一次式に置くと、`x` を読んだ後に `:=` を知らないので解析が止まる。
`path` は `a.b.c[i].d` と任意長なので、一次式として認識するには
**`path` を読み切ってから `:=` を見る投機的な解析が要る。** 演算子にすれば要らない。
**左辺が `path` であることは静的検査である。**

**`+` と `-` は左被演算子を要求しない。**
左に値があれば取り（加算・減算）、無ければ取らない（符号）。**二つの演算子ではなく一つ。**

| | 左を取る | 左を取らない |
|---|---|---|
| `+` `-` | 50 / 51 | — / 80 |
| `!` | **取れない** | — / 80 |
| `;` | **必ず取る** | **取れない** |

**比較と代入の非結合は束縛力では強制できない。** 別の検査で禁じる——
**混在も禁じる**（`a < b == c` も書けない）。
**`=>` は演算子ではない**——写像リテラルと `switch` の腕にしか現れない。

## BNF

**式が要る箇所には、すべて束縛力を書く。** `E@n` は `parse(n)` で読んだ式。

**束縛力はほぼ表から出る。表から出ないのは一箇所だけである。**

| 箇所 | | どこから来るか |
|---|---:|---|
| `:=` の右辺（宣言・欄） | **6** | **`:=` の右束縛力**（表）。だから `;` を吸わない |
| **`switch` の腕の値** | **6** | **表から出ない。** `;` を吸わせないための規定——`switch` に閉じ語が無いので要る |
| 脱出の被演算子 | **8** | **脱出の右束縛力**（表）。`;` も `:=` も吸わない |
| **それ以外すべて** | **0** | 閉じ記号や `,` や `case` で終わる |

`var x := 5;` が `var x := (5;)` にならないのは、**`:=` の右束縛力が `;` より高いから**である。

```
program   := E@0*

primary   := literal | IDENT | paren | block
           | construct | arraylit | maplit
           | decl | fndecl | flowdecl | structdecl
           | if | loop | while | nfor | switch
                                     脱出は一次式ではない。前置演算子である
paren     := '(' E@0* ')'
block     := '{' E@0* '}'

decl      := ('var'|'let'|'const') binding (',' binding)*
binding   := IDENT [':' valuetype] ':=' E@6
           | IDENT [':' valuetype 'alias'] '&=' IDENT
path      := IDENT ('.' IDENT | '[' E@0 ']')*
fndecl    := 'fn' IDENT '(' [params] ')' block ['->' type]
params    := param (',' param)*
param     := ['var'|'let'|'const'] IDENT ':' type  既定は let。注釈は省けない
flowdecl  := 'flow' FLOWNAME '=' escape
structdecl:= 'struct' IDENT '{' (fielddecl ';')* '}'
fielddecl := ('var'|'let'|'const') IDENT ':' valuetype [':=' E@6]

construct := 'new' type '(' [ctorargs] ')'
ctorargs  := IDENT ':=' E@0 (',' IDENT ':=' E@0)*  構造体：欄は名前で
           | E@0 (',' E@0)*                        配列・写像：位置で
arraylit  := '[' [E@0 (',' E@0)*] ']'
maplit    := '(' E@0 '=>' E@0 (',' E@0 '=>' E@0)* ')'
args      := E@0 (',' E@0)*

if      := 'if' paren E@0 ('elif' paren E@0)* ['else' E@0] 'fi'
loop    := 'loop' block
while   := 'while' paren block
nfor    := 'nfor' '(' IDENT ',' E@0 ',' E@0 ')' block
switch  := 'switch' paren arm+
arm     := 'case' E@0 '=>' E@6          ; を吸わない。最上位の ?? も消費しない

escape   := 'break' 'outward' escape        outward は脱出しか取らない
          | 'break' [被演算子]                break は値も取れる
          | 'continue' [escape]               continue は値を取れない
          | FLOWNAME ['(' escargs ')'] [被演算子]
escargs  := (escape | E@0) (',' (escape | E@0))*

type      := valuetype ['alias']
valuetype := 逆ポーランド。'array' は 1 つ、'map' は 2 つ取る（鍵、値の順）。
             最後にちょうど一つの型が残らねばならない
basetype  := 'u1'|'u8'|'u16'|'u32'|'i32'|'i64'|'f32'|'f64'|'str'| IDENT
```

> **被演算子とは、`escape` または `parse(8)` で読んだ式である。**

**`??` の除外だけは束縛力で書けない**——解析器で旗を一つ立てる。

**分岐は `;` を吸う。** 吸えば内面が空になり、**外界面は paradox** になる——
`( a; )` と同じであって、特別な振る舞いではない。

**腕は吸わない。** `switch` に閉じ語が無いので、`;` を吸うと
`switch` を終える `;` が書けなくなる。**腕の中で値を捨てるなら括弧を書く。**

- **束縛種があれば宣言、無ければ代入。** 綴り間違いが新しい名前を作らない。
  **代入は演算子である**（表の 7/6）。左辺が `path` であることは静的検査
- **`&=` の右辺は `IDENT`。** `&= a[i]` は文法で書けない
- **`alias` は `&=` の側にしか現れない。** 欄も `valuetype` なので書けない
- **`continue` の被演算子は脱出に限る**（値を取れない）。**`outward` は脱出を要求する**
- **`$repeat(break, n)` の第一引数は脱出。** 値の引数位置には置けないので `escargs` を分けた
- **`if` の分岐も `switch` の腕も一つの式。** `fi` と `case` が終わりを決める
- **`arm+` は区切りも終端も持たない唯一の繰り返し**なので、貪欲に読む。
  したがって**入れ子の `switch` は内側が後続の `case` を食う**——囲むこと

**文法は「何個並べてよいか」を決めない。** `block := '{' E@0* '}'` である。
並べた結果が規則に反するかは**数えて分かる**（静的検査）。

## 先読み

| | 見るもの |
|---|---|
| `paren` / `maplit` | 括弧の中の最上位に `=>` が現れるか。任意長 |
| `ctorargs` | `IDENT` の次が `:=` か。二トークン |
| `arm+` の終わり | 次が `case` か。**一トークン**（`case` はそのためにある） |
| 脱出の被演算子 | 次のトークンが式を始められるか。一トークン（`FIRST` 集合） |

**どれも文脈自由。** 名前解決が要る箇所は無い。

## 字句

```
IDENT    := (Unicode 文字 | '_') (Unicode 文字 | 数字 | '_')*
FLOWNAME := '$' IDENT
INT      := 数字 ('_' | 数字)* | '0x'… | '0b'… | '0o'…
FLOAT    := 数字+ '.' 数字+ [exp] | 数字+ exp
STRING   := '"' (通常文字 | escape)* '"'
```

予約語:

```
var let const fn flow struct new
if elif else fi
loop while nfor switch case
break continue outward
mod array map alias
```

- 行コメント `%`、ブロックコメント `%{ }%`（入れ子可）。**どちらも字句解析より前に消える**
- **改行に意味は無い**
- 数値リテラルは**ソースの表現のまま保持する。型接尾辞は無い**
- **`&=` は別名束縛なので、ビット論理積の複合代入は持たない**

# まだ決めていないこと

正直に挙げます。ここへの指摘は不要です。

- 標準ライブラリの境界（`$return`、UTF-8 のメソッド、写像の鍵の配列、配列の操作くらい）
- ホスト界面の契約（別名の無効化、方言が変えてよい範囲）
- **利用者がメンバ関数を宣言できるか、できるならどう書くか。**
  標準ライブラリの `.push()` `.len()` は既にあるものとして扱ってください
- **ラップ型を宣言する構文。** 宣言できることは決まっているが、書き方が決まっていない

# 想定する使われ方

見積もりの前提として、事実だけ挙げます。

- **ホストに埋め込まれる。** ホストが値の実体を持ち、この言語はそれを操作する
- **一回の実行は数ミリ秒から数秒。** プロセスは JIT が温まる前に終わる
- **起動が繰り返される。** 一つのホスト処理の中で何度も読み込み・実行される
- 実装は Rust。ホストは C / C++ / Rust を想定
