# Vaak — 必須構文の洗い出し

**構文の形は決めない。** 何が表現できなければならないかだけを並べる。
中核（言語が提供せねばならない）か、導出（他のもので書ける）かを判定する。

導出と判定できたものは**構文設計の対象から外れる**。それが本書の目的である。

判定の基準：
- **中核** — これが無いと他のもので書けない
- **導出** — 中核の組み合わせで書ける。無名標準ライブラリに置く（§2.4 二層構造）
- **未決** — 中核か導出かの判定に、まだ決めていないことが要る

## 1. 値と領域

| # | 表現できねばならないこと | 判定 | 備考 |
|---|---|---|---|
| 1.1 | 数値リテラル | 中核 | |
| 1.2 | 領域を明示的に作る | 中核 | ちょうど一つの値を持つ |
| 1.3 | 値を虚無へ潰す | 中核 | `;` に相当。**評価を伴う** |
| 1.4 | 空の領域が paradox を産む | 中核 | 規則であって構文ではない |
| 1.5 | paradox を既定値で置き換える | 中核 | フォールバック演算子に相当 |
| 1.6 | 文字列リテラル | 中核 | 字句層 |

**1.3 が言語の骨格である。** 「文の終わりに書く記号」ではなく「値を消す演算子」であること。
ここから「文と式の区別が無い」が出る。

## 2. 束縛

| # | | 判定 | 備考 |
|---|---|---|---|
| 2.1 | 名前に値を与える（新規） | 中核 | |
| 2.2 | 既にある名前に別の値を与える | 中核 | 2.1 と**別の操作**。同じ記号にしない |
| 2.3 | 同じセルを共有する（別名） | 中核 | レジスタ層に必須 |
| 2.4 | 値を複製して自分のセルを持つ | **未決** | 2.1 と同じか別か。集合体を入れると別になる |
| 2.5 | 複合更新（`+=` 等） | **未決** | 2.2 の糖衣なら導出。先行評価なら糖衣で足りるはず |

**閉じ込め（変更を外へ漏らさないこと）は 2.1 と 2.3 の選択で表現する。**
スコープ規則ではなく束縛の選択にする——書いた場所に見えるので。

## 未決を解くのに必要な決定

未決15項目は、**5つの決定**にぶら下がっている。これを先に決めれば残りは自動的に落ちる。

### 決定A：跳躍（goto / comefrom）を残すか

→ 3.12、3.13、8.2 の位置づけが決まる。

R4（汎用性）と R5（コンパイラビリティ）に照らす。弱版 §4.3 の下でも成立はする。
前身では「かなり Vaak 的」と評価されていた機構であり、実行時費用はほぼゼロ（使わなければ0）。
**費用ではなく、同一性と汎用性の問題として決める。**

### 決定B：巻き戻しの適用範囲

→ 7.5、8.4、2.3、そして**波括弧の意味が1つになるかどうか**が決まる。

候補：
- フレーム境界（関数）のみ
- レジスタ層のみ（TeX の save stack の本来の姿）
- 両方

**レジスタ層のみに絞れると、通常のコードから書き込みごとの費用が消える（R2 に直接効く）。**

### 決定C：ループ構文の梯子

→ 3.9、3.10、3.11 が決まる。

前身では `nfor` / `ifor` / `loop` / `while` の4段で、
`while` の値が反復回数（μ再帰）という設計だった。
**値を持たせるなら中核、持たせないなら導出。**

### 決定D：集合体の範囲

→ 2.4、2.5、5.2、5.4、5.7 が決まる。

「値を複製して自分のセルを持つ」（2.4）が独立した操作として要るかは、
配列・構造体を値として扱うかどうかで決まる。

### 決定E：無名の計算に引数を持たせるか

→ 4.6 が決まる。

値にならない（逃げ出せない）ことを構文で保証する形を検討中。
第一級関数を導入しないまま、界面だけ明示できる。

---

## 次にやること

**決定A〜E を順に片付ける。** そのあとで構文の形を設計する。

決定Aが最初である。跳躍の有無で、
言語が「TeX 埋め込み向け」に留まるか「やや汎用」になるかが変わり、
R4 の意味が確定するため。
