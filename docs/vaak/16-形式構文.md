# Vaak 形式構文

**束縛力表が一次仕様である。BNF はそれに従属する。**

前の版は BNF と束縛力表を並べて書き、**両者が同じことを言っているか確かめていなかった。**
その結果 `operand := escape | expr` が表と矛盾し、`break 5;` が `break (5;)` と読めた（C-61）。

**二重に書けば二重に間違えられる。** ここでは役割を分ける。

| | 何を決めるか |
|---|---|
| **束縛力表** | **式がどう組み合わさるか。** 一次仕様 |
| **BNF** | **一次式と固定形の構文だけ。** 結合を語らない |

BNF に式が要る箇所は、**すべて「束縛力 N から解析した式」と書く。**

---

## 1. 字句

```
whitespace  := ' ' | '\t' | '\r' | '\n'          区切りのみ。改行に意味は無い
linecomment := '%' … 改行まで
blockcomment:= '%{' … '}%'                       入れ子可
```

**どちらのコメントも字句解析より前に消える。** 中身は何でもよい。

```
IDENT       := (Unicode 文字 | '_') (Unicode 文字 | 数字 | '_')*
FLOWNAME    := '$' IDENT
INT         := 数字 ('_' | 数字)* | '0x'… | '0b'… | '0o'…
FLOAT       := 数字+ '.' 数字+ [exp] | 数字+ exp
exp         := ('e'|'E') ['+'|'-'] 数字+
STRING      := '"' (通常文字 | escape)* '"'
escape      := '\\' ('n'|'t'|'\\'|'"'|'0') | '\\x' 16進16進 | '\\u{' 16進+ '}'
literal     := INT | FLOAT | STRING
```

**数値リテラルはソースの表現のまま保持する。型接尾辞は無い。**

### 予約語

```
var let const fn flow struct new
if elif else fi
loop while nfor switch case
break continue outward
mod array map alias
```

**`outward` が予約語であることが要る**——さもなければ `break outward` の
`outward` が被演算子の識別子として読まれる。

---

## 2. 解析の規則（一次仕様）

**式は Pratt 解析で組む。**

```
parse(min_bp):
    左辺 := 前置または一次式を読む
    繰り返し:
        次の演算子の左束縛力 < min_bp なら止める
        演算子を消費し、右辺を parse(その演算子の右束縛力) で読む
```

| 演算子 | 位置 | 左束縛力 | 右束縛力 |
|---|---|---:|---:|
| `f(…)` `a[i]` `.m` | 後置 | 90 | — |
| `+` `-` `!` | 前置 | — | 80 |
| `*` `/` `mod` | 中置・左結合 | 70 | 71 |
| **`??`** | **中置** | **60** | **31** |
| `+` `-` | 中置・左結合 | 50 | 51 |
| `<<` `>>` | 中置・左結合 | 45 | 46 |
| `&` | 中置・左結合 | 42 | 43 |
| `^` | 中置・左結合 | 40 | 41 |
| `\|` | 中置・左結合 | 38 | 39 |
| `<` `<=` `>` `>=` `==` `!=` | 中置・**非結合** | 30 | 31 |
| `&&` | 中置・左結合 | 25 | 26 |
| `\|\|` | 中置・左結合 | 20 | 21 |
| `\|>` | 中置・左結合 | 15 | 16 |
| **脱出** | **前置** | — | **8** |
| **`:=` `&=` `+=` `-=` `*=` `/=` `mod=` `<<=` `>>=` `^=` `\|=`** | **中置・非結合** | **7** | **6** |
| `;` | 後置 | 5 | — |

**`;` は左辺の式が無くてもよい。** その場合、左辺は空の領域（値は paradox）である。

### 表から出ること

```
a + b / c ?? d + e     →  a + ((b / c) ?? (d + e))    右 31 < 加減 50
a ?? b ?? c            →  a ?? (b ?? c)               右 31 < 左 60 なので右結合
a ?? b < c             →  (a ?? b) < c                右 31 > 比較 30 なので吸わない
break 5;               →  (break 5);                  脱出 8 > `;` 5
break break break      →  3 段（前置の連鎖）
```

### 代入が表にあること

**代入は演算子である。** 一次式に置くと、`x` を読んだ後に `:=` を知らないので解析が止まる。
`path` は `a.b.c[i].d` と任意長なので、一次式として認識するには**無限先読みが要る**（C-62）。

```
x := 5;              →  (x := 5);        `;`(5) より高い
break x := 5         →  (break x) := 5   脱出の被演算子は parse(8) なので := を吸わない
a := b := c          →  非結合。別の検査で禁じる
```

**左辺が `path` であることは静的検査である。** 文法は決めない。

### 表が決めないこと

**比較の非結合は束縛力では強制できない。** 30 / 31 では `a < b < c` が左結合になる。
**別の検査で禁じる。**

**`=>` は演算子ではない。** 写像リテラルと `switch` の腕にしか現れない。表に置かない。

## 3. BNF（従属）

**結合を語らない。** 式が要る箇所は「束縛力 N から解析した式」と書く。
`E` を **`parse(0)` で読んだ式**の略記とする。

```
program   := E@0*

primary   := literal | IDENT | paren | block
           | construct | arraylit | maplit
           | decl | fndecl | flowdecl | structdecl
           | if | loop | while | nfor | switch

paren     := '(' E@0* ')'
block     := '{' E@0* '}'
```

**脱出は一次式ではない。前置演算子である**（表の「脱出」）。

**`paren` と `block` の中身の個数を文法は決めない**——領域の規則（§6）が決める。

### 束縛力の割り当て（C-63）

**束縛力はほぼ表から出る。表から出ないのは一箇所だけである。**

| 箇所 | | どこから来るか |
|---|---:|---|
| `:=` の右辺（宣言・欄） | **6** | **`:=` の右束縛力**（表）。だから `;` を吸わない |
| **`switch` の腕の値** | **6** | **表から出ない。** `;` を吸わせないための規定——`switch` に閉じ語が無いので要る |
| 脱出の被演算子 | **8** | **脱出の右束縛力**（表）。`;` も `:=` も吸わない |
| **それ以外すべて** | **0** | 閉じ記号や `,` や `case` で終わる |

`var x := 5;` が `var x := (5;)` にならないのは、**`:=` の右束縛力が `;` より高いから**である。

```
if (c) a; fi        構文エラー。parse(0) なら黙って paradox の分岐になっていた
let x := 1 / 0;     let x := (1/0) の後に ;。parse(0) なら ; を吸っていた
```

### 宣言・代入

```
decl      := ('var'|'let'|'const') binding (',' binding)*
binding   := IDENT [':' valuetype] ':=' E@6
           | IDENT [':' valuetype 'alias'] '&=' IDENT

path      := IDENT ('.' IDENT | '[' E@0 ']')*
fndecl    := 'fn' (IDENT | IDENT '.' IDENT) '(' [params] ')' block ['->' type]
params    := param (',' param)*
param     := ['var'|'let'|'const'] IDENT [':' type]        既定は let

flowdecl  := 'flow' FLOWNAME '=' escape

structdecl:= 'struct' IDENT '{' (fielddecl ';')* '}'
fielddecl := ('var'|'let'|'const') IDENT ':' valuetype [':=' E@6]
```

- **束縛種があれば宣言、無ければ代入。** 綴り間違いが新しい名前を作らない。
  **代入は演算子である**（表の 7/6）。左辺が `path` であることは静的検査
- **`&=` の右辺は `IDENT`**（C-53）。`&= a[i]` は文法で書けない
- **`alias` は `&=` の側にしか現れない**（C-58）。欄も `valuetype` なので書けない

### 構築とリテラル

```
construct := 'new' type '(' [ctorargs] ')'
ctorargs  := IDENT ':=' E@0 (',' IDENT ':=' E@0)*  構造体：欄は名前で
           | E@0 (',' E@0)*                        配列・写像：位置で
arraylit  := '[' [E@0 (',' E@0)*] ']'
maplit    := '(' E@0 '=>' E@0 (',' E@0 '=>' E@0)* ')'
args      := E@0 (',' E@0)*
```

### 制御

```
if      := 'if' paren E@0 ('elif' paren E@0)* ['else' E@0] 'fi'
loop    := 'loop' block
while   := 'while' paren block
nfor    := 'nfor' '(' IDENT ',' E@0 ',' E@0 ')' block
switch  := 'switch' paren arm+
arm     := 'case' E@0 '=>' E@6          ; を吸わない。最上位の ?? も消費しない
```

**6 は `;`（5）より高い。** `case 1 => foo;` は**構文エラー**になる——
`parse(0)` で読むと `;` を吸って腕の値が黙って paradox になる（C-62）。
**腕の後に来てよいのは `case` か、switch の終わりだけである。**

`??` の除外は**束縛力表の部分適用**であり、BNF では書けない。解析器で旗を一つ立てる。

```
switch (v) case 1 => 2 case 2 => 3 ?? 0
```

`?? 0` は **switch 全体**に付く。腕の中で使うなら括弧を書く。

**`if` の分岐と `switch` の腕は一つの式である。** したがって

```
if (c) a b fi                      構文エラー
if (c) ( a; b ) fi                 通る
switch (x) case 1 => foo() bar()   bar() は switch の外
```

**閉じる語が無くても終わりが決まる。**

**入れ子の `switch` は内側が `case` を食う**（C-61）。最後の腕に置くなら括弧が要る。

```
case 1 => ( switch (y) case 2 => 10 )
case 3 => 20
```

### 脱出

```
escape   := 'break' 'outward' escape        outward は脱出しか取らない
          | 'break' [被演算子]                break は値も取れる
          | 'continue' [escape]               continue は値を取れない
          | FLOWNAME ['(' escargs ')'] [被演算子]

escargs  := (escape | E@0) (',' (escape | E@0))*
```

> **被演算子とは、`escape` または `parse(8)` で読んだ式である。**

**8 は脱出の右束縛力である。** `;`（5）を吸わないので `break 5;` は `(break 5);` になる。

**ここが前の版で壊れていた**——`operand := escape | expr` と書いて `E` を使い、
表と矛盾していた（C-61）。**BNF に結合を語らせない**ことで直る。

- **`continue` は被演算子を取らない**（C-50）
- **`outward` は被演算子を要求する**（C-55）
- **`$repeat(break, n)` の第一引数は脱出**。値の引数位置には置けないので `escargs` を分けた

## 4. 型

```
type      := valuetype ['alias']
valuetype := 逆ポーランドで書かれた基底型と修飾子の列
basetype  := 'u1'|'u8'|'u16'|'u32'|'i32'|'i64'|'f32'|'f64'|'str'| IDENT
qualifier := 'array'（1つ取る） | 'map'（2つ取る。鍵、値の順）
```

**スタックで解析する。**

```
i64 array            i64 を積む → array が 1 つ取る
str i64 map          str と i64 を積む → map が 2 つ取る
str i64 array map    str と (i64 array) を積む → map が 2 つ取る
i64 array map        エラー。map は 2 つ取るが 1 つしか無い
```

**最後にちょうど一つの型が残らねばならない。** 領域の規則と同じ形である。

`alias` は修飾子ではない（C-48）。**最も外側にのみ置ける。**

## 5. 先読み

**曖昧ではないが、LL(1) では解けない。**

| | 見るもの |
|---|---|
| `paren` / `maplit` | 括弧の中の最上位に `=>` が現れるか。**任意長** |
| `ctorargs` | `IDENT` の次が `:=` か。**二トークン** |
| 脱出の被演算子 | 次のトークンが式を始められるか。**一トークン**（`FIRST` 集合） |

**どちらも文脈自由である。** 名前解決が要る箇所は無い（C-60）。

---

## 6. 文法が決めないこと

**以下は構文規則ではない。静的検査である。**

| | |
|---|---|
| 領域に置ける式の数 | 一つの領域は値を一つしか持てない |
| ループ本体の中身 | 何も残ってはいけない |
| 比較の連鎖 | `a < b < c` は書けてしまう。検査で禁じる |
| 別名の指す先 | 同じか外側のスコープ |
| 権限の伝播 | `let` から `var` 別名は作れない。破壊的メンバ関数は `var` を要求する |
| 脱出の段数 | フレームを越えない |
| `alias` 引数に渡せるもの | 名前だけ |
| 名前の存在 | 未宣言の名前への代入 |
| 代入の左辺 | `path` でなければならない |
| 代入・比較の連鎖 | 非結合。`a := b := c` は書けてしまう |
| **値の数え方** | **脱出する経路は値を置かない。数えるのは正常に続く経路だけ**（C-62） |

**文法は「何個並べてよいか」を決めない。** `block := '{' E* '}'` である。
**並べた結果が規則に反するかは、数えて分かる。**

これは意図的である。**構文で禁じれば、なぜ禁じられるかが構文の都合になる。**
領域の規則から出る、という導出を保ちたい。

**静的エラーは複数あってよい**（C-61）。走らせる前に分かるので、数を絞る必要が無い。
**実行時エラーだけが二種である**——消費されなかった paradox と、フレームを越える脱出。

## 7. 前の版の誤り（記録）

| | |
|---|---|
| `expr` を定義していなかった | 定義した |
| `=>` を演算子表に置いていた | 誤り。写像リテラルと腕にしかない |
| `escapeexpr := escapehead escapeexpr` | `continue 123` が書けた。分けた |
| `structdecl` が `fielddecl` を使っていなかった | 直した |
| **代入の生成規則が無かった** | `m /= 10` が文法に無いのに例で使っていた |
| `args` で `$repeat(break, n)` を表現できなかった | `escargs` を分けた |
| `??` の非対称を階層化 BNF で書こうとしていた | 束縛力表に変えた |
| `armvalue` を使いながら定義していなかった | 定義した |
| `binding` の別名側で `alias` が二重 | `valuetype 'alias'` に直した |
| `escape` が一次式と前置演算子の両方にあった | 一次式から外した |
| `fielddecl` の型が `alias` を書けてしまった | `valuetype` に直した |
| `FLOWNAME` が `IDENT` と区別できなかった | `$` を名前の一部にした（C-60） |
| `outward` が予約語だと書いていなかった | 予約語に加えた |
| **`operand := escape \| expr` が束縛力表と矛盾していた** | 表に従属させた（C-61） |
| **代入演算子を束縛力表に載せていなかった** | 載せた（C-62） |
| **`E` を `parse(0)` の略記にして、全箇所を監査しなかった** | **略記を廃止した**（C-63） |

**最後の三件は同じ誤りである**——「式が要る箇所に、束縛力を書かずに済ませた」。

C-61 で「すべて束縛力 N から解析した式と書く」と決めたのに、
**`E` という略記を作って、それが `parse(0)` だと一箇所で決めただけだった。**
**略記は一つの束縛力しか持てないのに、式が要る箇所は複数の束縛力を要求する。**

**略記を廃止した。** すべての箇所に `E@n` と書く。書き忘れれば文法が成り立たない。
