# 構文設計 2 — 束縛

意味論は C-6 / C-12 / C-16 / C-17 / C-19 / C-20 / C-30 / C-33 / C-35。

---

## 1. 二つの束縛演算子が、一つの対で説明される

まず、宣言と代入を貫く規則を置く。

| | 何をするか |
|---|---|
| **`:=`** | **この名前が指すセルに、値を書く**（複製して） |
| **`&=`** | **この名前が、別のセルを指すようにする** |

**宣言でも代入でも同じ意味である。**

```
var x := 5;      x のセルを作り、5 を書く
x := 7;          x のセルに 7 を書く

var y &= x;      y が x のセルを指す
y := 9;          y が指すセル（＝ x のセル）に 9 を書く。x も 9 になる
y &= z;          y が z のセルを指すようになる。x は変わらない
```

**`:=` はセルの中身に作用し、`&=` は名前の指す先に作用する。** 別名かどうかで規則が変わらない。

---

## 2. 宣言

```
var x : i64 := 5;
let y := 10;
const z : u8 := 20;

var a &= x;
let b : i64 alias &= x;
```

- 束縛種（`var` / `let` / `const`）が**新規宣言の印**である
- 型注釈は識別子に付く（`:`、C-30）。省略できる
- `&=` で宣言すれば別名になる。型を書くなら `alias` を付ける

### 型の書き方

**完全後置修飾**（C-30）。左から順に修飾を重ねる。

```
i64                  i64
i64 array            i64 の配列
i64 alias            i64 への別名
i64 array alias      i64 の配列への別名
i64 alias array      i64 への別名の配列
```

**読む順序が書く順序と一致する。** `Array<Ref<i64>>` のように内から外へ読み返さない。

### 新規宣言と再束縛を分ける

```
var x := 5;      宣言
x := 7;          再束縛
xx := 7;         エラー。xx は宣言されていない
```

**束縛種の有無だけで見分けがつく。** 綴り間違いが新しい名前を作らない。

---

## 3. 三つの束縛種

| | 禁じるもの | 軸 |
|---|---|---|
| `var` | 何も | 経路 |
| `let` | この識別子を経由したセルの変更 | 経路 |
| `const` | そのセルの変更（誰からも） | セル |

```
let x := 5;
x := 7;          エラー。let はこの識別子からの変更を禁じる
var y &= x;      エラー。let から var 別名は作れない（権限が伝播する）
let y &= x;      よい
```

```
var a := 5;
const b &= a;    この時点で a のセルが凍る
a := 7;          エラー。セルが凍っている
```

## 4. 分解は、複数宣言で足りる

```
let x := p.x, y := p.y;
```

**専用の構文を持たない。**

C-4 で「分解は束縛の形で与える」と決めたが、**束縛の形とは複数宣言のことでよい。**

- `{ }` を分解の記法に使えない——三つの単位を作る記法だから（C-20 まで）
- `( )` も使えない——領域を作る記法だから
- 新しい括弧を導入する理由が、**便利さ以外に無い**

そして複数宣言には利点がある。**どの欄を取ったかが字面に出る。**
`let x, y := p;` のような形は「p のどの欄か」を規則で決めることになり、
**読み手が規則を覚える対象が増える。**

代数的型を持たないので、分解は**常に成功する**（C-4）。したがって
「失敗しうる構文」に見せる必要も無い。

## 5. 前方宣言は無い

**持たない**（C-36）。

> **関数宣言は、それを囲むスコープ全体で見える。**
> **変数宣言は、宣言の位置から先で見える。**

```
fn is_odd (n : i64) {
    if n == 0 then 0 else is_even(n - 1) fi
} -> u1;

fn is_even (n : i64) {
    if n == 0 then 1 else is_odd(n - 1) fi
} -> u1;
```

前方宣言は**実行器が上から読むという都合**であり、PHECL 原則8（実行器の都合で
人間が使える構文を制約しない）に当たる。

関数宣言は何も実行しないので、スコープ全体で見えても**実行順序は変わらない。**

## 6. 複合代入

**糖衣である**（C-12）。

```
x += E       ≡  x := x + E
x -= E
x *= E
x /= E
x mod= E
x <<= E
x >>= E
x ^= E
x |= E
```

### `&=` は複合代入に使えない

**`&=` は別名束縛である。** ビット論理積の複合代入は**持たない。**

```
x := x & y;      こう書く
```

`&=` は埋め込みの中核機構であり（C-2 の議論、C-19、C-20）、譲れない。
**衝突する糖衣の方を落とす。**

`^=` は前身で「未評価の計算の複製」だったが、遅延を捨てて空いた（C-6）。
**ビット排他的論理和の複合代入として使う。** 前身の意味とは無関係である。

## 7. 例

```
% ふたつの点の距離の二乗
fn dist2 (a : Point alias, b : Point alias) {
    let dx := a.x - b.x, dy := a.y - b.y;
    dx * dx + dy * dy
} -> i64;

var p : Point := Point ( x := 0, y := 0 );
var q : Point := Point ( x := 3, y := 4 );

p.x := 1;                     % メンバへの代入。. はアクセスなので複製しない

let d := dist2(p, q);         % 別名で受けるので複製されない
```

**大きい構造体は `alias` で受ける。費用が署名に出る**（C-20）。

## 決着した細部

### 別名の型注釈は省略できる（C-37）

```
var y &= x;                  よい
var y : i64 alias &= x;      よい。ただし alias が無ければエラー
```

### `const` の凍結はスコープで解ける（C-37）

```
var a := 5;
{
    const b &= a;    a が凍る
    a := 7;          エラー
}
a := 7;              よい。b のスコープが終わったので解けた
```
