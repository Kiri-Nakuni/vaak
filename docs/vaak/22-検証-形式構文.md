# 検証 3 — 形式構文

[16-形式構文.md](16-形式構文.md) を、実際に解析してみて確かめる。

---

## 1. 束縛力表をトレースする

`??` の非対称（左 60 / 右 31）が意図どおりか。Pratt 解析を手で回す。

| 式 | 解析 | 期待 | |
|---|---|---|---|
| `a * b ?? c` | `*`(70) を消費 → 右を 71 で解析 → `b`。戻って `??`(60) を消費 | `(a*b) ?? c` | ✓ |
| `a ?? b * c` | `??` 消費 → 右を 31 で解析 → `*`(70) ≥ 31 なので吸う | `a ?? (b*c)` | ✓ |
| `a ?? b + c` | 右を 31 で解析 → `+`(50) ≥ 31 なので吸う | `a ?? (b+c)` | ✓ |
| `a + b ?? c` | `+` 消費 → 右を 51 で解析 → `??`(60) ≥ 51 なので吸う | `a + (b ?? c)` | ✓ |
| `a ?? b ?? c` | 右を 31 で解析 → `??`(60) ≥ 31 なので吸う | `a ?? (b ?? c)` | ✓ 右結合 |
| `break 5;` | 脱出の右束縛力 8 で解析 → `5`。`;`(5) < 8 なので止まる | `(break 5);` | ✓ |

**六つとも意図どおり。** 「左は乗除の次、右は加減より下」が `60 / 31` で正確に表現できている。

### 🟡 発見：`??` の右は比較を吸わない

`??` の右束縛力 31 は、比較の左束縛力 30 より**高い**。

```
a ?? b < c        →  (a ?? b) < c
```

`??` の右辺に比較を書くには括弧が要る。**決定（「右は加減より下」）どおり**だが、
**明記していなかった。**

### 🔴 発見：比較の非結合が表で強制されない

比較を「非結合」と書いたが、左束縛力 30・右束縛力 31 では

```
a < b < c        →  (a < b) < c
```

と**左結合になる。** 非結合にするなら**表とは別の検査**が要る。

`(a < b)` は `u1` で、`u1 < c` は型が合わないので**型検査器が捕らえる**が、
**構文で禁じたいなら明示が要る。**

## 2. 私が書いた文法のバグ

### 🔴 `armvalue` を定義していない

```
arm := 'case' expr '=>' armvalue
```

**`armvalue` がどこにも無い。** 曖昧さの解消規則（最上位の `??` を消費しない）を
表現するために名前を付けたが、定義を書き忘れた。

**修正**：`armvalue := expr`（ただし最上位の `??` を消費しない）。
これは束縛力の話なので、**BNF ではなく解析器の旗**として書くしかない。

### 🔴 `binding` の別名側が壊れている

```
binding := IDENT [':' type] ':=' expr
         | IDENT [':' type 'alias'] '&=' IDENT
```

`type` は既に `valuetype ['alias']` を含む。**`type 'alias'` は二重である。**

**修正**：

```
binding := IDENT [':' valuetype] ':=' expr
         | IDENT [':' valuetype 'alias'] '&=' IDENT
```

`:=` の側は `valuetype`（`alias` を書けない、C-58）。
`&=` の側は `valuetype 'alias'`（書くなら `alias` が要る）。

### 🔴 `escape` が一次式と前置演算子の両方になっている

`primary` に `escape` を並べ、束縛力表にも「脱出（前置）右束縛力 8」がある。**二重である。**

**修正**：`primary` から外す。**脱出は前置演算子である。**
`flowdecl := 'flow' IDENT '=' escape` のように名前で参照する箇所は残す。

### 🟡 `fielddecl` の型が広すぎる

```
fielddecl := ('var'|'let'|'const') IDENT ':' type [':=' expr]
```

**欄は値の場所なので `alias` を書けない**（C-48）。`valuetype` にする。

## 3. 先読みが要る箇所

**曖昧ではないが、LL(1) では解けない。** 記録しておく。

### `paren` と `maplit`

```
( a )              領域
( a => b )         写像リテラル
```

`(` の後を読み進めて `=>` が現れるかで決まる。**任意長の先読みが要る。**

括弧の中は一つの領域なので `( a; b => c )` のような形もありうる——
**`=>` が最上位に現れるかどうか**を見る必要がある。

### `ctorargs`

```
new T ( x := 1 )       欄を名前で
new T ( x )            位置で
```

`IDENT` の次が `:=` かどうかで決まる。**二トークン先読み。**

### `FLOWNAME`

**唯一、名前解決が要る箇所**（16-形式構文 §6 に記載済み）。

## 4. 通った確認

### `if` の分岐が一つの式であることは、文法が保証する

```
if := 'if' paren expr ('elif' paren expr)* ['else' expr] 'fi'
```

分岐は `expr` 一つなので、

```
if (c) a b fi        構文エラー（`fi` を期待して `b` が来た）
if (c) ( a; b ) fi   通る
```

**「腕は一つの値」が構文で出ている。** 静的検査に回さずに済んでいる。

### `switch` の終端も、腕が一つの値だから決まる

```
switch (x) case 1 => foo() bar()
```

腕は `foo()` で終わり、`bar()` は switch の外。**閉じる語が無くても一意に決まる。**

外部の吟味で「先読みできない」と指摘されたが、**腕が一つの値であることを
読み落としていた**——`foo() bar()` が一つの腕になる可能性が無い。

### 宣言と代入が構文で分かれている

```
var x := 5;      decl
x := 5;          assign
xx := 5;         assign。xx が未宣言なら名前解決でエラー
```

**束縛種の有無だけで見分けがつく**（C-35 の意図が文法に出ている）。

### `&=` の右辺が名前に限られている

```
binding := … | IDENT […] '&=' IDENT
assign  := … | IDENT '&=' IDENT
```

**`&= a[i]` が文法で書けない。** C-53 を静的検査ではなく構文で表現できた。

## 5. まとめ

| # | 判定 |
|---|---|
| 1 | 🔴 `armvalue` を定義していなかった。**私のバグ** |
| 2 | 🔴 `binding` の別名側で `alias` が二重。**私のバグ** |
| 3 | 🔴 `escape` が一次式と前置演算子の両方にある。**私のバグ** |
| 4 | 🔴 比較の非結合が束縛力表で強制されない。**別の検査が要る** |
| 5 | 🟡 `fielddecl` の型が広すぎる（`alias` を書けてしまう） |
| 6 | 🟡 `??` の右が比較を吸わないことを明記していなかった |
| 7 | 🟡 先読みが要る箇所が三つ（`paren`/`maplit`、`ctorargs`、`FLOWNAME`） |

**束縛力表は正しかった。** 六つのトレースがすべて意図どおりで、
`??` の非対称が数字で正確に表現できている。

**バグは三つとも私の書き落とし**であり、意味論の問題ではない。

**そして収穫が一つ**——`if` の分岐と `switch` の腕が「一つの式」であることを
**文法が保証している**ので、静的検査に回さずに済んでいる。
外部の吟味が「switch の終端は先読みできない」としたのは、**この点の読み落としだった。**
