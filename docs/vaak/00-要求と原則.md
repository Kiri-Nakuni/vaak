# Vaak — 要求と原則

**Vaak**（वाक्、ヴァーク）。サンスクリットで「言葉」「発話」。拡張子は `.vaak`。

前身は REod（[../../legacy/reod-tier1/](../../legacy/reod-tier1/) に凍結）。
REod の名は read / Runtime Error / 面食らう構文の3つを誠実に示唆していたが、
そのうち2つが設計変更で当てはまらなくなったため改名した。

### 名前について記録しておくこと

**当初は χωρα（Chora）を採った。** プラトン『ティマイオス』の「場」——形も色も持たず、
生成するものを受け取る器——であり、「領域はちょうど一つの値を持つ」という中核規則を
名前が直接指していた。akasha（虚無）と同じ概念の、別の言語系からの対でもあった。

**先行する同名の言語があったため破棄した。**

次に Xukong（虚空、ākāśa の漢訳）を検討した。空いてはいたが、発音の注記を必要とした。
V4k も検討したが、`4` が「4K」を誤って示唆し、かつ英語圏の読み手が「ヴァーク」と読まない——
**優しさを狙って選んだ綴りが、注記なしでは優しくない**という理由で退けた。

`Vaak` は発音の注記を必要としない唯一の候補だった。

**ただし、名前が名指すものが変わったことは記録しておく。**

| | 名前が名指すもの |
|---|---|
| REod | read / Runtime Error / 面食らう構文（**言語の性質**） |
| χωρα | 領域（**中核概念**） |
| **Vaak** | 語ること（**言語であること一般**） |

中核概念——領域・虚無——を名前が指さなくなった。**意図した選択である。**
PHECL 本文「Syntax は Semantic を誠実に示唆しなければならない。それができないのなら、
一切示唆するべきではない」に照らすと、`Vaak` は言語について一般的な示唆をするだけで、
意味論について嘘の約束をしない。サンスクリットを知らない読み手には何も示唆しない。

## §0 要求

Vaak の同一性は意味論ではなく**要求**にある。現在の意味論はこの要求を満たす解の一つであって、
要求を満たさなくなった意味論は捨てる。REod がそうなった。

### R1 起動が速いこと

ホストの起動ごとに処理系が立ち上がる。コンパイル相を持たず、即座に実行を始められること。

> 測定（REod、参考値）：起動 0.00 秒。CPython の 0.01 秒より速い。

### R2 JIT が温まる前にホストが終了する作業負荷で速いこと

TeX のような、短命な処理を大量に呼ぶホストが主戦場である。JIT は助けに来ない。
**したがって素の解釈速度が全部を決める。**

> 測定（REod、参考値）：3項ループ 300万周で CPython の 5.7倍遅い。
> 起動の優位が実行の劣位を補えるのは **約24,000反復（≈20ms）まで**。
> **起動の優位は定数、実行の劣位は線形。定数は必ず負ける。**
>
> これが REod を捨てる直接の理由である。R1 は設計で満たしていたが、
> R2 は願望で満たしていた。

### R3 そのための、素朴で根本的な表現能力

R1・R2 を満たすには、解釈が単純でなければならない。
したがって表現能力は**素朴で根本的なもの**に限る。豊かさは目的ではない。

### R4 やや汎用的であること

TeX への埋め込みが主用途だが、そこに限定しない設計にする。
埋め込みホストの都合が言語の意味論を決める場面は、記録したうえで最小に留める。

### R5 JIT / AOT コンパイル可能であること（優先度：低）

意味論の判定基準として使う。**目標ではなく基準である。**

前身では「コンパイル可能性は目標ではなく**帰結**である」としていた。
基準に上げることで、次が直ちに従う：

> **跳び越される区間が構文解析されなくてよい**という性質（REod §4.3）は採らない。
> 解析できないものはコンパイルできない。
>
> 弱版——構文は通る、名前解決と型は通らなくてよい——なら両立する。

### 標準実装は真のインタプリタである

R5 は意味論への基準であって、実装への要求ではない。
**標準実装（POSIX Vaak）はコンパイル相を持たない。** R1 を守るため。

コンパイル可能な意味論を選びつつ、標準実装はコンパイルしない——
これは「抽象化を使う自由と、抽象化を剥がす自由の双方を残す」ことの実装版である。

## §1 原則

### 1.1 主原則

> **意味論を理解した人間の素朴な思考が、そのまま——導出された構文として——出ること。**

二つのことを言っている。

**素朴であること。** 「簡単」ではない。簡単なだけなら、やりたいことを書ければよい。
Vaak が簡単に書けるようにするのは**やること**であって、やりたいことではない。

**導出であること。** 構文は意味論から出る。規定された対応表を覚えさせない。

前身の `;` がこの好例だった——「文の終わりにセミコロンを書く」という規則を覚えるのではなく、
`;` が値を虚無へ潰すことを知っていれば、どこに書くかは自分で出てくる。
覚える対象が規則ではなく機構になる。

### 1.2 境界基準

「素朴に」は個別には常に正当化できるので、境界を先に置く。

> **ある構文が許されるのは、読み手がソースだけから
> 「どの演算が、どの順で走るか」を決められるときに限る。**

判定例：

| | |
|---|---|
| 遅延評価 | **落ちる**。実測で4人の読み手全員が実行順序を誤読した |
| 高階関数・map / filter | **落ちる**。どの演算が走るかが呼び先次第 |
| 演算子宣言 | **通る**。宣言されていて静的 |
| `;` が値を虚無へ潰す | **通る**。しかも規則を覚える必要がない |
| 領域はちょうど一つの値を持つ | **通る**。書かれたものを数えれば分かる |
| 巻き戻しで代入が黙って消える | **落ちる**。どの代入が効くかが隠れる |

この基準は PHECL 原則7（処理順序を人間から隠蔽しないこと）を、判定できる形にしたものである。

### 1.3 名前と意味の単射

**一つの意味論の内側で、一つの構文が二つの意味を持ってはならない。**

意味論を固定したうえでの要求である。実行の意味論と道具（パーサ・LSP）の意味論が
違うことは違反ではない——それぞれの内側で一意ならよい。

前身ではこれが破れていた。波括弧が3つの意味を持っていた（[§3.3](#33-波括弧の多義性)）。

**加えて、二段目の検査を課す。**

> その名前は、**この言語が**別のところで持っている機構を連想させないか。

**言語間の単射——他の言語での意味を連想させないか——をどう扱うかは未決とする（[§4](#§4-未決)）。**
前身では意図的に放棄したが、その前提（遅延評価）が消えたので、判断をやり直す。

### 1.4 PHECL との関係

[PHECL](../PHECL.md) は**高等教育用言語のための原則**であって、実用言語のためではない。
Vaak はこれを上位規範として採用しない。**メンタルモデルの参考として参照する。**

R1〜R5 と PHECL が衝突する場合、**衝突していること自体を記録したうえで、要求を優先しうる。**

現時点で、Vaak の判断のうち PHECL が直接支持しているもの：

| Vaak の判断 | PHECL |
|---|---|
| 先行評価にする | 原則7「処理順序を人間から隠蔽しないこと」 |
| 波括弧の多義性を解消する | 原則6「異なる処理を同じ構文に抽象化しないこと」、戒1 |
| 素朴であること | 原則2「処理が単純素朴であること」 |
| 単純化を隠さない | 本文「単純化するならば、単純化していることを隠してはならない」 |

**PHECL 本文の中心はこの一文である。**

> Syntax は Semantic を誠実に示唆しなければならない。それができないのなら、一切示唆するべきではない。

前身の束縛演算子 `:=` はこれに反していた——他言語で正格な代入を示唆しながら、遅延サンクを束縛していた。
**誠実な示唆ではなかった。**

### 1.5 却下理由を捨てない

判断を変えたとき、**変える前の理由を消さない。** 誤りが見つかったときも、誤りとして残す。

前身の decisions.md（D-1〜D-70）がこの規律で書かれており、再設計の過程で実際に効いた——
D-70 の却下理由に誤りが見つかった。「`:=` の代わりに中立な記号を使う」案を移行コストを理由に却下していたが、
PHECL 本文（「示唆できないのなら一切示唆するべきではない」）に照らすとそちらが正道だった。

## §2 保持するもの

前身から持ち越す。いずれも**実装費用が軽いことが測定で確認されている**。

### 2.1 領域・虚無・paradox・`;`

- 領域はちょうど一つの値を持つ。内部に何も置かれていなければ、その値は paradox である
- `;` は左の値を評価してから捨て、内部を空にする
- paradox は消さねばならない。消費するのは `;`、フォールバック演算子、そしてホストである

**静的な構造規則であり、実行時費用はゼロ。** 書かれたものを数えれば検査できる。

虚無（前身では akasha）は値でも型でもなく、領域を占めない。名前は再検討する（[§4](#§4-未決)）。

### 2.2 完全後置型修飾

`i64 array`。**`:` は識別子に、`->` は領域に付く**（C-30）。構文のみ。費用ゼロ。

### 2.3 作用素式と、動的段数の脱出

`break` が段数を取り、段数が実行時の値でよい。脱出の後に何をするかを伴える。
制御構造そのものに名前を与えられる第三の束縛種。

> 測定：AST 実装で **42行**。実行時費用は `break` の瞬間だけ。
> 外部の見積もりは一貫して「`break` は数行」と値付けしたが、実測はその2桁上だった——
> つまりこれは Vaak の特徴的な機構であり、かつ安い。

動的スコープにも遅延評価にも依存していない。**捨てる理由がない。**

### 2.4 二層構造

中核と、無名で読み込まれる標準ライブラリ。
標準ライブラリに書かれるものは Vaak で書かれており、中核の形をいつでも直接書ける。

> 抽象化を使う自由と、抽象化を剥がす自由の双方を人間に残すこと。

前身では下層が**義務**だったため二層が二層になっていなかった（強制点を知らないと正しく書けなかった）。
先行評価では明示が**選択**になるので、ここで初めて二層構造が機能する。

## §3 捨てるものと理由

### 3.1 動的スコープ

**理由：R2。** 名前をコンパイル時にスロットへ解決できず、性能の床を作っていた。

副次的に、字句スコープにすると**遅延評価も安くなる**——どのスロットがサンクを持つかが
束縛の形から静的に分かるので、読むたびの検査が消える。**一つ捨てて二つ取り返せる。**

失うもの：サンクが環境を捕捉しないこと、関数も動的であること。
そして**前身の意味論の大半がここから導出されていた。**

TeX の相続分は失わない。**TeX が要求しているのは群の退出で状態が戻ることであって、
名前を呼び出し元で引くことではない。** 両者は分離できる。

### 3.2 既定の遅延評価

**理由：PHECL 原則7、および §1.2 の境界基準。**

> 測定：`plain3_forcing.reod` の7つの観測点に対し、**4つの読み手全員が実行順序を誤読した**。
> 出力を与えた後でさえ、一つの機構（遅延＋メモ化）に四つの別々の説明を与えた読み手がいた。
> 隠蔽は成功していた。

さらに、動的スコープを捨てた時点で**遅延の導出元が消える**。
前身では「サンクが環境を捕捉しない」ことの帰結として遅延が正当化されていた。
字句スコープではそれが失われるので、遅延は帰結ではなく選択になる——
そして選択としては、原則7に落ちる。

消える問題（いずれも前身で測定済み）：

- メモ化が巻き戻らず、消された世界の値が生き残る
- 生成の文脈と強制の文脈が違う
- `x := f(x)` が発散する
- 引数は正格だが呼び出しは遅延

### 3.3 波括弧の多義性

**理由：PHECL 原則6・戒1、および §1.3。**

前身では波括弧が3つの意味を持っていた。測定：

| | `break` の段数 | 巻き戻し |
|---|---|---|
| 裸の `{ }` | 数える | 退出時に適用（戻る） |
| `if c { }` | **数えない** | **無し** |
| `loop { }` | 数える | checkpoint（正常終了で破棄） |

```
let x := 1;  { x := 99; }             → x = 1
let x := 1;  if 1 == 1 { x := 99; }   → x = 99
```

**同じ記法、逆の挙動。** 前身の仕様は「`{ }` の意味は1つ。規律は何に付いているかが決める」と
規定していたが、これは戒1が名指しで禁じている**ディスパッチによる差異の回収**である。

解決の方向（[10-構文](10-構文.md) で確定させる）：

- `if` の本体は領域ではありえない。`break` に透明でなければならないから。
  ゆえに**領域の記法で書いてはならない** → `if … fi` 型
- 巻き戻しをフレーム境界（および レジスタ層）に寄せ、
  裸のブロックとループ本体を**同一の意味にする** → `loop … pool` は不要

`loop … pool` を採らないのは、**意味論は素朴になるが構文論が素朴でなくなる**ため。
主原則は両方に掛かる。

### 3.4 `^=`（未評価の計算の複製）

遅延が無いので、複製すべき未評価の計算が存在しない。

集合体の**値複製 vs 参照別名**という区別は Tier 2 相当で実際に要るが、
**同じ記号を再利用しない。** 「未評価の計算の複製」と「値の深いコピー」は
たまたま両方が複製なだけで、機構としては無関係である（§1.3 の二段目の検査）。

### 3.5 §4.3 の強い版（跳び越される区間は構文解析されない）

**理由：R5。** 弱版（構文は通る／名前解決と型は通らなくてよい）を採る。

失うのは「壊れた字句列を隠す」用途だけで、そこは**字句層のブロックコメント**で代替する。
前身では tree-sitter の外部スキャナに近似として実装済みであり、
**近似が仕様に昇格する**形になる。

## §4 未決

- **虚無の名前。** 前身では akasha（आकाश）。言語名が Vaak になったことで、
  同じ概念を二つの言語系から取ることになる。整理するか、そのままにするか
- **言語間の単射をどう扱うか**（§1.3）。前身では意図的に放棄したが、前提が消えた
- **巻き戻しの適用範囲。** フレーム境界のみか、レジスタ層のみか。
  TeX の save stack が保存しているのは本来レジスタとパラメータである
- **`goto` / `comefrom` を残すか。** 弱版 §4.3 の下でも成立するが、
  R4（汎用性）と R5（コンパイラビリティ）に照らして要否を判定する
- **無名関数の形。** 引数を取り、適用形でしか書けないブロック——
  値にならないので逃げ出しようがない——を検討中
- **`break` をブロックから外すか。** `if` が式であれば用途が減る。
  ただし作用素式・`getdepth` の全部がここにぶら下がっている
