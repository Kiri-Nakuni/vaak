# 構文設計 3 — 制御

意味論は C-3 / C-4 / C-10 / C-21 / C-23 / C-24 / C-26 / C-32 / C-34。

---

## 0. 記法が二種に分かれる理由

**本体がブロックである構文と、そうでない構文がある。**

| | 本体 | 記法 |
|---|---|---|
| `loop` / `while` / `nfor` | **ブロック**（領域・スコープ・脱出段の三つ） | **`{ }`** |
| `if` / `switch` の分岐 | **被演算子位置**（領域のみ） | **`{ }` を使えない** |

`if` の分岐が `break` に透明でなければならない（C-10）以上、それは脱出段ではない。
**`{ }` は三つ全部を作る記法なので、使えない。**

したがって `if` と `switch` だけがキーワードで閉じる。**様式ではなく必然である。**

---

## 1. `if`

```
if (c) a else b fi
if (c) a fi
```

- **条件は直後の一つの領域。** `u1` でなければならない（C-21）
- 分岐は被演算子位置。`else` と `fi` が境界になる
- **`then` は要らない。** 条件が区切られていれば、次に来るものが then 側だと決まる

### 条件が括弧で区切られる理由

分岐の境界は `else` / `fi` が与えるが、**条件と then 側の境界を与えるものが無い。**
だから条件は自分で区切る。

```
if (n == 0) 1 else 0 fi
```

`{ }` で書いても同じ結果になる——`{ }` も領域を作るので。

```
if {n == 0} 1 else 0 fi        通る。ただし推奨しない
```

**帰結として受け入れる。** ただし `{ }` はスコープと脱出段も作るので無駄が多い。
**コーディング規則では `( )` を推奨する。**

### `else` が無ければ paradox

```
if (c) 1 fi
```

条件が偽なら内界面はアーカーシャであり、外界面は paradox（C-14 規則2）。
そのまま置けばエラーなので、**`??` で受けるか `;` で潰す。**

```
let x := if (c) 1 fi ?? 0;
if (c) print(1) fi;
```

### `elif`

```
if (c1) a elif (c2) b else c fi
```

**糖衣である。** `if (c1) a else if (c2) b else c fi fi` と同じ。
`fi` が積み上がるのを避けるためだけのもの。

---

## 2. `loop`

```
loop { … }
```

本体はブロック。**末尾は `;` か脱出**（C-24）。

**`loop` の値が paradox になることはない。** 少なくとも一周するので、
領域が `{}` になり得ない。値は常に反復回数か、`break` が置いた値である。

---

## 3. `while`

```
while (c) { … }
```

- **条件は直後の一つの領域。任意の整数型。`≠ 0` で継続**（C-21）
- 本体はブロック

### 0周が paradox であることは帰結である

`while (c) { hoge }` の領域は `{ [hoge] [hoge] … }` である。
0周なら `{}` になり、**中がアーカーシャのブロックなので paradox に落ちる**（C-14 規則2）。

**「0周は paradox」という規定ではない。空のブロックの規則が適用されているだけである。**

```
let n := while (c) { … } ?? 0;      一度も回らなければ 0
```

---

## 4. `nfor`

```
nfor (i, start, count) { … }
```

- 三つの被演算子を一つの括弧に並べる。**束縛する名前、開始、回数**（C-38）
- 歩幅は取らない。**要るなら配列を作る**（C-8）
- `i` は本体の中で `let`——書き換えられない
- `count` が 0 以下なら 0周。領域は `{}` になり **paradox**

```
nfor (i, 0, n)             i は 0 から、n 回
nfor (i, 0, a.len())       配列をちょうど一周する
```

**終点ではなく回数である。** 終点にすると、含む／含まないのどちらを選んでも
名前が嘘になるか `- 1` が要るかのどちらかになる（C-38）。

---

## 5. `switch`

```
switch (e) case P1 => V1 case P2 => V2
```

- 対象は直後の一つの領域
- **腕の右辺は一つの値**。`=>` は `??` より強く結合する
- **閉じる語を持たない。** `case` 以外が来た時点で終わる（C-39）
- どの腕にも当たらなければ内界面はアーカーシャ → **paradox**（C-26）

```
let name := switch (n) case 0 => "zero" case 1 => "one" ?? "many";
```

**既定の腕を持たない。** `??` が受ける。

### 閉じる語が要らないのは、腕が一つの値だから

`if … fi` が閉じる語を要するのは、分岐が式を丸ごと取るからである。
switch は腕が一つの値なので、`case` が尽きた時点で終わりが決まる。**必然の違いである。**

### 副作用だけの腕

```
switch (val) case 1 => (a();) case 2 => (b();) ;
```

`(a();)` は内界面がアーカーシャなので外界面は paradox。末尾の `;` が潰す。

**腕の位置に裸の `;` は書けない。** アーカーシャにしたいなら `( )` で輪廻させる。

## 6. 脱出

```
escapeexpr := escapehead escapeexpr | escapehead [expr]     右結合
escapehead := 'break' ['outward'] | 'continue'
            | '$' IDENT '(' args ')' | FLOWNAME
```

| | |
|---|---|
| `break` | 1 段抜ける。値を置かない |
| `break E` | 1 段抜けて、E を外界面に置く |
| `break break break` | **3 段抜ける** |
| `$repeat(break, n)` | **n 段抜ける**。n は実行時の値でよい |

**段数は反復でのみ表す**（C-50）。`break 5` は「5 を置く」であって「5 段抜ける」ではない。

**`break` の被演算子は、外界面で評価される作用素式である**（C-32）。
値はその特別な場合にすぎない。

### 段数の書き方

`break break break` と並べれば静的な段数になる。動的な段数は合成で書く。

```
$repeat(break, getdepth())        深さぶんだけ抜ける ＝ 関数から抜ける
```

これが標準ライブラリの `return` である（二層構造、C-2 §2.4）。

### `continue`

```
continue                 1段抜けて、外側のループを次の周回へ
```

**独立した機構ではない。** 「1段抜けて継続する」の名前である（C-23）。

### フレームを越える

```
break outward break 1
```

**非推奨**（C-34）。構造化プログラミングの見た目で書きたいときと、足元を撃ちたいときだけ。

```
fn main () { break outward break 1; }
main();                                  → exit 1
```

### `getdepth()`

フレーム基準からの段数を返す（C-23）。**フレームは関数本体、または最上位。**

## 7. 例

```
% 線形探索。見つからなければ paradox
fn find (a : i64 array alias, x : i64) {
    nfor (i, 0, a.len()) {
        if (a[i] == x) $repeat(break, getdepth()) i fi;
    }
} -> i64;

let pos := find(xs, 42) ?? (0 - 1);
```

```
% 桁の和
fn digit_sum (n : i64) {
    var s := 0, m := n;
    while (m) {
        s += m mod 10;
        m /= 10;
    };
    s
} -> i64;
```

`while (m)` は「m が 0 でない間」である。**`m != 0` と書かなくてよい**——
`while` の条件は `≠ 0` の検査だから（C-21）。
