# 領域・スコープ・脱出段・ブロック

**この文書が必要になった理由を先に書く。**

設計の議論中に、私（Claude）は領域の意味を**三度続けて取り違えた**。

1. 「ループの領域では後の周回が前を置き換える」——恣意的な規定を導出と偽った
2. 「本体の値はループの領域に入らない」——過剰に訂正した
3. 「ループは N 項の演算子として本体の値を消費する」——消費しないのに消費すると言った

いずれも**領域を、スコープやブロックや脱出段と混同していた**ことに起因する。
前身 REod が波括弧に三つの意味を持たせて破綻したのと**同じ混同**である。

したがって、これらを分けて定義する。

---

## 三つの単位と、一つの構文

**三つの概念は平行している。いずれも「単位」であり、何の単位かだけが違う。**

| | 定義 |
|---|---|
| **領域**（region） | **値**を持つ単位 |
| **スコープ**（scope） | **名前**が見える単位 |
| **脱出段**（break level） | **脱出**が数える単位 |

そして**ブロック `{ }` は構文であって概念ではない。** ブロックが何であるかは、
上の三つの**どれを同時に作るか**で決まる。

**三つが独立であることは、この定義から自明である。** ある単位であることは、
別の単位であることを含意しない。

### 領域

> **値を持つ単位。**

これだけである。「ちょうど一つの値を持つ」は追加規則ではなく、
**「値を持つ単位」に含まれている**——単位が持つのは値であって、値の集まりではない。

したがって `1 2` は規則違反である。一つの単位に値が二つある。

領域は**ブロックより細かい**。`1 + 2` には少なくとも三つある。

```
[ [1] + [2] ]
```

`+` は左右の領域から値を取り、**自分の領域に結果を一つ置く**。

**領域の外から見た値と、領域の中にある値は別のものである。**
`+` の全体の値 3 は、中の 1 や 2 から**選ばれた**のではない。`+` が**産んだ**。

#### 領域の値と、領域内の値

**この二つを混同してはならない。**

| | |
|---|---|
| **内界面** | 領域の内側から値が置かれる面。計算中の値やリテラル |
| **外界面** | 領域の値として外から見える面。**これが「実在する値」である** |

「領域内の値」は**内界面**のことであって、**内側に入れ子になった領域のことではない。**

**最上位の領域の外界面は、Vaak の意味論に属さない**（C-31）。その向こうはホストである。

#### 値と虚無と paradox

1. **領域は終結した時点で値を持つ**
2. **内界面がアーカーシャ**であるか、**内界面に置かれた値が paradox** であるなら、
   **外界面は paradox** である
3. paradox は**アーカーシャに潰す**（`;`）か、**`??` で消す**かしなければならない

#### 終結と、エラー

> **領域が paradox を持って終結したら、その時点でエラーである。**
> **終結を撤回できるのは `??` だけ。例外はない。**

**深い伝播は起きない。** `5/0` は、`/` という演算子が自分の内界面に paradox を置いた結果、
その領域の値が paradox になって終結する。内側の領域から伝播してきたのではない。

したがってエラーは常に、**最も内側の、paradox を産んだ領域**で起きる。追跡が要らない。

```
let x := 5/0;
```

`:=` の右辺の領域が閉じた時点——`5/0` が終結した時点——で値は paradox である。**そこでエラー。**
「実在する値を要求する地点の一覧」のようなものは要らない。**帰結である。**

### スコープ

> **名前が見える単位。**

Vaak は字句スコープである（C-2 以降）。内側で導入された名前は外側から見えない。
**巻き戻しの機構ではない**——内側の名前が外に漏れないのは、
ジャーナルが戻しているからではなく、**別のスロットだから**である。

### 脱出段

> **脱出が数える単位。**

段数は反復で表す（C-50）——`break break break` で 3 段。`getdepth()` はフレーム基準からの段数を返す。

**領域と一致しない。** 領域は `1 + 2` に三つあるが、被演算子位置は脱出段ではない。

### ブロック

> **`{ }` という構文。**

前身の破綻は、`{ }` が場所によって違う組み合わせを作っていたことにあった。

## 三つは独立である

| | 領域 | スコープ | 脱出段 |
|---|---|---|---|
| 演算子の被演算子位置 | **○** | × | × |
| 裸のブロック `{ }` | ○ | ○ | ○ |
| ループ本体 | ○ | ○ | ○ |
| 関数本体 | ○ | ○ | ○（上限） |
| **`if` の分岐** | **○** | **×** | **×** |

**`if` だけが列を跨いでいる。** 値を持つ（領域である）が、`break` に透明でなければならない
（脱出段ではない）。

```
loop { if c { break; } … }
```

この `break` はループを抜けねばならない。`if` を抜けるのでは意味をなさない。

**したがって `if` の分岐を `{ }` で書いてはならない。** `{ }` は三つ全部を作る記法だから。
これが `if … fi` 型を要求する理由であり、様式の問題ではない。

---

## `if` の分岐は被演算子位置である（C-10 で決定）

`if` は演算子であり、分岐はその被演算子位置である。したがって領域だが、スコープでも脱出段でもない。

- **`break` に透明であることが導出で従う。** 被演算子位置は脱出段ではないので
- `if` 全体の値は `if` が産む。`+` が和を産むのと同じ
- **帰結：分岐の中で導入した名前は外へ漏れる。** 閉じ込めたいなら裸のブロックを使う

## ループの値が反復回数である理由（再掲）

この区別があると、C-3 が短く言える。

- ループ本体が値を置けば、それは**ループの領域に溜まる**。ループは消費しない
- N ≥ 2 で規則違反。ゆえに**本体は値を置いてはならない**（静的に課す）
- 空いた領域に、**ループが自分の値を置く**——反復回数
- 0周なら中はアーカーシャで、外から見た値は **paradox**

「ループが自分の値を置く」は `+` が和を置くのと同じ圏の**規定**である。導出ではない。

## 検査の言葉

エラーメッセージはこの区別を使う。

| 状況 | 言うべきこと |
|---|---|
| `1 2` | 「この領域に値が2つあります」（構文の誤りではない） |
| `loop { 1 }` | 「ループ本体は値を置けません。周回のたびに溜まります」 |
| 見えない名前 | 「この**スコープ**からは見えません」 |
| 深すぎる `break` | 「**脱出段**が足りません。ここは N 段です」 |

**「文の書き方が違います」とは言わない。** 何が起きたかを言う。
