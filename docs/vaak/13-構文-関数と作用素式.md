# 構文設計 4 — 関数と作用素式

意味論は C-15 / C-19 / C-20 / C-23 / C-30 / C-32 / C-33 / C-35 / C-36。

---

## 1. まず、宣言がなぜ `;` で終わるか

**句読点ではない。paradox の消費である。**

宣言は値を置かない。したがって宣言の領域は内界面がアーカーシャであり、
**外界面は paradox** になる（C-14 規則2）。

```
var x := 5 var y := 6
```

**二つの paradox が同じ領域に置かれる。規則違反である。**

```
var x := 5; var y := 6;
```

`;` が paradox をアーカーシャへ潰すので、囲む領域には何も置かれない。

> **`;` が宣言の後に要るのは、宣言が paradox を産むからである。**
> 「文の終わりに書く記号」ではない。

そして**型注釈の終端も、これで足りる。**

```
fn f () { … } -> i64 array;
```

`;` が来るまでが型である。改行に意味を持たせる必要が無い。

---

## 2. 関数宣言

```
fn name (params) { body } -> T;
```

- `->` は**本体の領域**に付く（C-30）。だから本体の直後に来る
- 本体はブロック。領域・スコープ・脱出段の三つを作る
- **本体の領域がフレームである**（C-23）——`getdepth()` の原点、`break` の上限
- 前方宣言は無い。**宣言はスコープ全体で見える**（C-36）

```
fn gcd (a : i64, b : i64) {
    if (b == 0) a else gcd(b, a mod b) fi
} -> i64;
```

### 引数

```
fn f (a : i64, b : i64 alias, var c : i64) { … } -> i64;
```

- 引数は識別子なので `:` で注釈する（C-30）
- **束縛種を省略すれば `let`**。書き換えられない
- `var` と書けば書き換えられる
- **複製か別名かは型が決める**（C-20）。`alias` と書けば別名で受ける

```
fn dist2 (a : Point alias, b : Point alias) { … } -> i64;
```

**大きい構造体は `alias` で受ける。費用が署名に出る。**

### 返り値

- **別名は返せない**（C-19）
- 値は深く複製される（C-33）。ただし返される局所は直後に死ぬので、
  **実装は移動してよい**——観測できない

---

## 3. 呼び出し

```
f(a, b)
```

引数は各引数の領域に置かれる。**引数の領域が閉じた時点で値が確定する。**

呼び出しは後置なので最も強く結合する。

```
f(a) ?? d           →  (f(a)) ?? d
a.m() ?? d          →  (a.m()) ?? d
```

---

## 4. `|>`

```
x |> f(a)        ≡  f(x, a)
x |> f()         ≡  f(x)
x |> f() |> g()  ≡  g(f(x))
```

**構文の水準の糖衣**（C-15）。第一級関数を要求しない。

**`|>` は自由関数に適用する。** `x` の型の名前空間を探しに行かない——探すなら `.` を書く。

```
xs |> sum()          自由関数 sum(xs)
xs.len()             xs の型の名前空間の len
```

優先順位が低いので、左に式全体を置ける。

```
a + b |> f()     →  (a + b) |> f()
```

## 5. 作用素式

**値でも関数でもない第三の束縛種。** 前身から変更しない。

```
flow name = 作用素式;
```

### `=` であって `:=` ではない

`:=` は**セルに値を書く**（C-20）。`flow` は**セルを作らない**——
名前が構文の断片を指すだけである。書くべき値が無いので `:=` は使えない。

**`=` は定義であって束縛演算子ではない。**

| | セルを持つか | 何を名指すか |
|---|---|---|
| `var` / `let` | 持つ | 値 |
| `const` | 持つ（凍っている） | 値 |
| `fn` | 持たない | 関数 |
| **`flow`** | **持たない** | **作用素式** |

### 使用位置で読み直される

作用素式の本体は、**使うたびに使用位置で評価される。**
だから `getdepth()` が使用位置の深さを返す。

```
flow $return = $repeat(break, getdepth());
```

`return` を関数のどの深さから書いても、そこの `getdepth()` が効く。

### `$repeat`

```
$repeat(op, n)
```

作用素 `op` を `n` 回重ねる。`n` は実行時の値でよい。

```
$repeat(break, 3)              break break break と同じ
$repeat(break, getdepth())     フレームの上限まで抜ける ＝ 関数から抜ける
```

`$` は**作用素式の組み合わせ子**を示す。値の世界の関数呼び出しと区別する印である。

### `getdepth()`

フレーム基準からの段数を返す（C-23）。**フレームは関数本体、または最上位。**

---

## 6. 無名標準ライブラリ

すべてのプログラムの前に読み込まれる（二層構造）。Vaak で書かれており、
**中核の形をいつでも直接書ける。**

```
flow $return = $repeat(break, getdepth());
```

`return 1;` は `$repeat(break, getdepth()) 1;` と書いても同じである。
**抽象化を使う自由と、剥がす自由の双方を残す。**

---

## 7. 例

```
fn is_odd (n : i64) {
    if (n == 0) 0 else is_even(n - 1) fi
} -> u1;

fn is_even (n : i64) {
    if (n == 0) 1 else is_odd(n - 1) fi
} -> u1;
```

**前方宣言が要らない**（C-36）。

```
% 線形探索。見つからなければ paradox
fn find (a : i64 array alias, x : i64) {
    nfor (i, 0, a.len()) {
        if (a[i] == x) $return i fi;
    }
} -> i64;

let pos := find(xs, 42) ?? (0 - 1);
```

`return i` は `$repeat(break, getdepth()) i` である。
`nfor` の中（1段）と関数本体（1段）で深さ2なので、二段抜けて関数の値になる。

見つからなければ `nfor` が最後まで回り、その値は反復回数——
**ではなく、本体が `;` で終わるので `nfor` の領域はアーカーシャ**。
関数本体の内界面もアーカーシャなので、**外界面は paradox** になる。

---

## 提案：`fn` の本体を省略できるか

C-36 で前方宣言を落としたので、**本体の無い `fn` は文法から消えた。**

```
fn f (a : i64) -> i64;      これは何でもない
```

**エラーにする。** 「宣言だけ」という形が意味を持たないので、書けてはいけない。

## 提案：引数の既定を `let` にすること

```
fn f (a : i64)          a は let
fn f (var a : i64)      a は var
```

**すべての引数に `let` と書かせない。** 書き換える引数の方が少数なので、
少数の側に印を付ける。

C-35 は宣言について `var` / `let` / `const` を明示させるが、
**引数は宣言と違って「呼び出し側から値が来る」ことが確定している**ので、
既定を置いても読み手が迷わない。

**判断を求める。** 明示させる方が一貫するが、`fn f (let a : i64, let b : i64)` は冗長である。
