# 意味論のどこが非直感的すぎるか

現行の意味論を実測で精査し、**驚きが設計から正当化されるもの**と、**正当化されないもの**に分けた。

判定の基準はひとつ。

> **驚きそのものは咎めない。咎めるのは、驚きが黙って起きること。**

REod は言語間の単射性を意図的に放棄している（D-70）。したがって「他言語と違う」ことは欠陥ではない。欠陥なのは、**間違ったまま動いてしまう**ことである。

---

## 1. 関数からの外部代入が黙って消える 🔴 正当化されない

```
fn bump () { n += 1; 0 } -> i64;
let n := 0;
let a := bump();  a += 0;
let b := bump();  b += 0;
print(n);
```

→ **`0`**。カウンタが数えない。エラーも警告も出ない。

`#[global]` を付ければ動く:

```
fn bump () { #[global]
n += 1; 0 } -> i64;
```

**機構としては正しい。** 関数本体は group であり、退出時にジャーナルが適用される（§4.8）。`#[global]` が書き込みレベルを指定する（D-19 撤回後の設計）。導出は一貫している。

**問題は沈黙である。** 「フレームの外で束縛された名前へ、`#[global]` なしで代入した」ことは**書かれたものを見れば分かる**。§1.5 が読み取り時検査を掲げている以上、これは検査できる位置にある。

**提案**：`#[global]` なしの外部代入を**エラーにする**。属性は「見えない既定を明示する」ためではなく「既定と違うことを宣言する」ためのものなので、既定側が黙って捨てるのは属性の役割と食い違っている。

これは本書で唯一、**設計の変更を推す項目**である。

## 2. メモ化は巻き戻らない。代入は巻き戻る 🔴 決めるべき（深刻）

同じブロック境界が、同じセルへの2種類の書き込みを**別々に扱う**。

| ブロック内で起きたこと | 退出時 |
|---|---|
| `x := 99`（代入） | 巻き戻る |
| `b` の強制（メモ化） | **残る** |

最も鋭い形はこれである。

```
let a := 1;
let b := a + 10;
{
    a := 5;
    let ig := b; ig += 0;      % ここで b が強制される
}
print(a);        % 1
print(b);        % 15
print(a + 10);   % 11
```

`b` は `a + 10` と書かれていて `15` を持つ。同じ行に書かれた `a + 10` は `11`。
そして **`a` が 5 だった状態はもうどこにも存在しない**——ブロックが巻き戻した。

> **`b` は、消された世界で計算された値を持ち出している。**

### 「スナップショットだから当然」ではない

C の `int b = a + 10;` も関係を維持しない。それは普通である。REod の違いはそこではない。

> **`:=` は関係を維持する——最初の強制まで。そこで維持をやめる。そしてその瞬間は書かれたものに現れない。**

さらに巻き戻しが加わると、**スナップショットを撮った状態そのものが後から消えうる**。

### 三択であり、どれも代償がある

| 案 | 失うもの |
|---|---|
| **メモを残す（現状）** | 巻き戻された状態の値が生き残る。上の例 |
| **メモも巻き戻す** | 強制の副作用が複数回起きる。`;` が forcing point になる Tier 2.1 以降は特に痛い |
| **依存追跡して選択的に巻き戻す** | 依存関係の記録が必要。§4.8「規律は確保元によらず一様」が崩れる |

### (d) 第四の案——観測は (a) と同一、語彙が違う

外部の指摘による。(a)(b)(c) は「巻き戻しはセルの状態に対する操作である」という前提を共有している。**その前提を外す。**

> **save/restore が復元するのは環境（名前からセルへの対応）であり、セルそのものではない。セルは一度生成されると、参照する名前の生存期間とは独立して存在し続ける。強制とメモ化はセルに対する操作であり、巻き戻りの対象になることはない。**

観測結果は (a) と完全に一致する——区別できない。変わるのは**説明**である。

| | 言い方 |
|---|---|
| (a) | メモ化だけが巻き戻りの例外 |
| (d) | 巻き戻るのは名前の束縛だけ。セルは**最初から対象外** |

(a) の言い方だと読み手は「例外があるなら他にもあるのでは」と身構える。(d) は §4.8 の「一様」を**傷つけない**——一様性の例外ではなく、**一様性の適用範囲の確認**になる。

しかも同じ語彙が、これから出るはずの別の問いにも答える。「巻き戻ったスコープで新しく作られたセルはどうなるか」→ 指す名前が無くなるだけで、強制済みなら値は残る（到達不能になるので実装上は回収対象だが、それは意味論の話ではない）。

**(d) を採る。** 中身は (a) で、仕様には「巻き戻りの対象は環境であってセルではない」と**対象範囲の宣言として**書く。§4.8 に例外節を足す必要はなくなる。

### 確認済み：他の束縛演算子は一様である

| | 結果 |
|---|---|
| `let b &= a;` してブロック内で `a := 99` | 退出後 `b` も `a` も 1。巻き戻る |
| ブロック内で `b &= a` | 退出後 `b` は元に戻る |
| `let c ^= a;` してブロック内で `a := 99` | 退出後 `c` は 1 |

**`&=` と `^=` は規律に従っている。例外はメモ化だけである。**

## 3. 生成の文脈と強制の文脈が違う 🟢 正当化される（記述が弱い）

```
fn deep (n : i64) { k } -> i64;
fn mid  (n : i64) { k := n; deep(99) } -> i64;
let k := 0;
print(mid(7));
```

→ **`99`**。`k := n` を書いた場所で `n` は 7 である。

§4.6「名前解決は常に解決時点の環境で行われる」の帰結であり、規則としては既出。動的スコープを採った以上、これは避けられない。

**問題は例が弱いこと。** 現在の §4.6 の例はブロックによる隠蔽で、直観に反しない。上のように **同じ名前が2つのフレームに同時に存在し、書いた側でなく強制した側が勝つ**形にしないと、規則の射程が伝わらない。

**提案**：§4.6 の「どの環境で強制するか、という問いは立たない」の直後に置く。あそこで「問いは立たない」と書いた以上、**では何が驚きなのか**を同じ場所で示すのが誠実である。

## 4. `x := f(x)` が発散する 🟢 正当化される（人間工学は悪い）

```
let x := 1;
x := f(x);      % 実行時エラー: 自己参照 thunk を強制しました（発散）
```

`:=` は式を束ね直すだけなので、右辺の `x` は新しい `x` を指す（D-17、§4.6）。

**沈黙しない**——明確なエラーが出る。回避も1行:

```
#[immediate]
x := f(x);      % 2
```

正当化される。ただし**あらゆる言語で最も普通の更新の書き方**がこれなので、`#[immediate]` を毎回書かせるのは重い。§5 の未解決項目「再束縛の構文糖」はここに掛かっている。

## 5. 引数は正格。呼び出しは遅延 🟢 正当化される（対で示されていない）

```
let z := 5 / 0;             % 通る
fn f (v : i64) { 0 } -> i64;
print(f(5 / 0));            % 0 除算エラー（v は使われないのに）
```

一方:

```
let r := f(5 / 0);          % 通る。呼び出し自体がまだ起きていない
```

3つとも同じ規則から出る——**強制点が入れ子になっている**。関数引数は強制点だが、呼び出しに到達するのは外側が強制されたときである。

正当化される。ただしこの3つは**必ず並べて示す**必要がある。1つだけ見せると必ず誤読される（実測で4人中4人）。

## 6. ブロックコメントに句点が書けない 🟡 別途対処

```
comment;
    ここは実行されない。      ← この「。」で字句エラー
label _comment_;
```

`%` コメントは字句解析より前に消えるので何でも書ける。ブロックコメントは字句解析の後（`goto` 走査）なので、字句が通る文字しか置けない（D-69）。

**日本語で書く言語として実害がある。** ブロックコメントは「壊れたコードを隠す」ためのものなのに、**散文の方が先に通らない**。

対処案は D-69 の議論に3つ挙げてある。字句解析器がエラーを**遅延する**（認識できない文字をトークンにして、使われた時だけ落とす）のが筋がよい——遅延評価という言語の性格とも合う。

---

## まとめ

| # | 項目 | 判定 |
|---|---|---|
| 1 | 関数からの外部代入が黙って消える | 🔴 **設計を変えるべき**（エラーにする） |
| 2 | メモ化が巻き戻らない | 🔴 **§4.8 の例外として明記すべき**（現状維持を推す） |
| 3 | 生成の文脈 ≠ 強制の文脈 | 🟢 記述を強くする |
| 4 | `x := f(x)` の発散 | 🟢 構文糖を検討（§5 既出） |
| 5 | 引数は正格・呼び出しは遅延 | 🟢 3つ並べて示す |
| 6 | ブロックコメントの字句制限 | 🟡 字句解析器を寛容にする |

**1 と 2 以外は、書き方の問題である。** REod の意味論は概ね一貫していて、非直感的すぎるのは1箇所だけだった——そしてそこは、非直感的だからではなく**黙っているから**問題である。
