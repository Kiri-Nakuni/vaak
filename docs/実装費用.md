## 重い条項

### 1. §4.3 認識的スキップ（最も重い）

> `goto` は対応する `label` の直前まで読み飛ばす。走査は波括弧の深さのみを認識する。

この一文が **208行** を要求している。木を持たない以上、「実行せずに正しく通過する」ためのコードを、**構文ごとに**書く必要があるからである。`skip_stmt` `scan_primary` `scan_bin` `scan_unary` `scan_expr` `skip_type` `skip_type_to_eol` `scan_to_label_with` `match_pair` `match_paren` `match_brace`。

木走査インタプリタにはこの項目が**存在しない**。部分木を評価しなければ飛ばしたことになる。

**これは構文ごとの税である。** Tier 2 が `nfor` / `ifor` / `while` / `switch` / `typ` を足すと、そのそれぞれに走査側の対応が要る。**「残りを入れても倍にならない」という見立てが崩れるとすれば、ここが唯一の候補である。**

### 2. 動的段数の脱出と作用素式（181行）

`resolve_after` 29 ＋ `parse_op_expr` 75 ＋ `parse_repeat` 37 ＋ `exec_operator_chain` 40。

`break` が段数を持ち、段数が動的でありうること（`$repeat(break, getdepth())`）、そして脱出の**後に何をするか**（`After`）を運ぶこと。3つが合わさって、単なる `Result` の variant では済まなくなっている。

外部の見積もりでは `break` は一貫して「数行」と値付けされた。実測はその2桁上である。

### 3. D-23 三つの巻き戻し規律（151行）

`if` 本体＝レベルなし／ループ本体＝checkpoint（正常終了で破棄）／裸ブロック・関数本体＝group（退出で適用）。

3つあること自体が費用であり、`push_group` `pop_group` `push_checkpoint` `discard_checkpoint` `apply` `set` `set_global` `record_var` `record_comefrom` `jump_unwind` `enter_frame` `leave_frame` に分散している。

### 4. D-31 フレーム基準（分散していて単独では測れない）

`getdepth()` の原点・`break` の上限・巻き戻しの床・`goto` の走査範囲が同一境界を共有する。一点に統合されている分、実装は**安い**。ただし `frame_span` がインタプリタ全体に貫通しており、Tier 1 のバグの多くがここから出た。

### 5. D-18r アトリビュートの改行終端（分散）

行が意味を持つため、`lexer.rs` が**物理行と論理行の2つ**を追跡する（D-66 で `%` が論理行を進めないため）。`skip_type_to_eol` `at_line` `set_line_offset` `line_offset` がその帰結。tree-sitter 側では外部スキャナ（`scanner.c`）を要求している。

## 結論

> **カーソル機械の経済性は「何を計算するか」に効いており、「どこを実行するか」には効いていない。**

REod が普通の言語処理系より安い部分（値・環境・クロージャ）と、高い部分（制御転送・走査）は、はっきり分かれている。そして高い方は §4.3〜§4.5 に集中していて、これらは PraTeX への埋め込みという §0 の要求から出ている。

**費用は設計の失敗ではなく、設計の所在を示している。**
